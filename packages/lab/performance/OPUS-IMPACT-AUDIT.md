## Implemented slice: delete count-only full-patch reads

Before the change, the workbench rail asked for the whole uncommitted diff, with no `paths`, whenever the project workbench was shown, only to sum line counts. On a cache miss that's one `git` process per changed file, every untracked file read, and all patch text sent over IPC. The key includes the snapshot revision and `gcTime` is 0, so a mounted rail refetched after each worktree revision it observed. Opening the scope menu mounted three more path-less diff reads (uncommitted, staged, unstaged) just for counts. The panel's working scopes request explicit `paths`, so these keys differ from the panel's working-scope key. Query caching means this isn't a guaranteed extra read on every interaction, but nothing the panel loads ever answers them. The fixture below measured 3 extra reads on the first menu open with the old code.

Edits (pre-edit copies in `/tmp/nyte-opus-audit/git-slice/*.pre`):

- `app/src/workbench/workbench.tsx`: removed `useVcsDiff`, `diffRead`, `diffScopeStats` and the `useChangesViewOptions` read, plus the `stats` prop on `ChangesRow`.
- `app/src/workbench/rail-status.tsx`: `ChangesRow` shows only the snapshot file count. Removed the +/- span and the `ChangeScopeStats` import.
- `app/src/workbench/workbench.stylex.ts`: deleted the now-unused `railStats`, `railAdded` and `railRemoved`.
- `app/src/workbench/change-scopes.ts`: added `ChangeScopeRead` arm `{kind:"files"; fileCount}`, meaning the paths are known and the line totals are unknown, not zero. `workingTreeScopeOptions(snapshot)` takes no diffs. Deleted `diffRead`, `diffScopeStats` and `WorkingTreeDiffs`.
- `app/src/workbench/changes-toolbar.tsx`: inlined the deleted `WorkingTreeScopeItems` along with its three `useVcsDiff` reads. `ScopeRadioItem` renders the file count for `files`. Corrected the `scopeStats` prop comment, which said the menu reads the rest itself.
- Regression proof in the existing scope fixture. `changes-scope-preload.ts` counts `workspace.vcs.diff` calls. `changes-scope.browser-test.tsx` records the read count and menu rows, opens and closes the menu, then selects Unstaged and waits for its patch to load and render. `changes-scope.test.ts` asserts that opening the menu adds 0 reads, the rows show `Uncommitted 1 file`, `Staged 0 files` and `Unstaged 1 file`, and selecting Unstaged adds exactly 1 read and renders `src/working.ts`. I swapped in the pre-edit toolbar and `change-scopes.ts` temporarily, and the test failed with `4 !== 1`. Then I restored both and checked them byte for byte.

Semantic change: the rail and the working-tree menu rows show file counts, not +/- totals. The toolbar trigger still shows totals for the selected scope, from the panel's own read. The commit and turn rows are unchanged. No protocol, core, host or bridge contract changed.

Checks: `pnpm exec tsc --noEmit` in `packages/app` passes, and `oxlint` and `oxfmt --check` are clean on the eight files. The seven focused changes test files (11 tests) pass. In one earlier run, `changes-stack` failed under parallel load and then passed twice alone. It imports none of the edited modules. In the full app suite, 5 tests fail in 4 files I didn't modify (`control-targets`, `icons`, `models-settings-login`, `web/registry`). None of them import edited modules, and the failures are about composer hit areas, icon ink, login and registry. I didn't run a baseline, so I can't say whether they fail without these edits.

## Deletion-first order with stop gates

1. A: delete row and neighbour preloading. The other agent owns this and has already applied it. Stop gate: the zero-request browser test above, plus a click-to-paint check that switching didn't regress noticeably.
2. Git count deletion. Done. Stop gate: the user accepts losing +/- totals in the rail and menu. If they're wanted back, add one numstat metadata read (`git diff --raw --numstat -z`, one process per scope, untracked totals reported as unknown). Don't restore the patch reads.
3. B-host `sessionRoot`. Stop gate: runtime policy tests still pass, with `readSession` counted at 0 for list and auth.
4. C-small fact patch in `rowHolds`/`listedInfo`. Stop gate: measure `track()` and the 5 s sweep during a long run. Only consider durable state if that measurement shows O(history) cost per commit that an in-process cache keyed by an immutable tip can't remove.
5. D next: drop the `paths` default that means "everything" in `diff`, take commit rows from `scopeRead().files`, add the `unknown` arms from finding 8, then fetch by viewport window. Stop gate: stacked review scrolls end to end, and the rename `from` survives into rows.
6. E: per-call byte budget on patch reads, a typed `too_large` outcome, and migration of the `untrackedPatch` marker. Stop gate: the 10.5 MB fixture is bounded on the host, and the existing commit, stage and push tests are unchanged.

The broad transactional projection stays blocked until step 4's measurement exists. Before anyone considers it, it needs a defined behaviour for old-binary writers, a write-lock cost budget for rewinds, a Postgres equivalent and atomic rebuild publication.
