Checks that a provider's current credentials work. It answers `verified`, `unverified` when the
provider has no way to check, or `failed` with the reason.

## When to call it

After a login or key change, or when a run failed with an authentication error and the user wants
to know whether the credentials are the cause.

## Access

Needs `owner` authority. Host scope.

## Example

Request body:

```json
{ "provider": "anthropic" }
```

Response:

```json
{ "kind": "failed", "reason": "The API key was rejected." }
```

## Errors

- `unavailable` when the host was built without models. A failed check is the `failed` outcome,
  not an error.
