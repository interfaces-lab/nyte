title: sessions.start
description: Starts a chat with its first message.
---

Creates a chat and admits its first message in one commit, so no session exists without a
message. It answers once the session's `before_send` hooks have decided the message, with the
session id, the receipt and the message id. A hook that refuses, a failing hook, or a stop before
the decision removes the session and fails the call.

## When to call it

When the user sends the first message of a new chat. Until then the chat is a draft only the
client knows. [Send messages](/docs/sdk/guides/send-messages#start-a-chat-with-its-first-message)
covers each input.

`id` names the chat, its first message and its receipt. Mint it when the draft is created and send
it with every retry: the same id with the same input returns the same start.

`project` starts the chat in a project. A child starts in its parent's project without it, and a
side chat in none. The first top-level chat in a project becomes its coordinator in the same commit.
A further top-level start in that project is refused as `invalid`; send to its existing coordinator
instead. A project that is archived, or works in another folder, is also refused as `invalid`.

## Access

Any principal with `participant` authority. Host scope: the session doesn't exist yet. The
workspace is `workspace`, else the parent's, else the host's default. A start that passes
`configuration` from a client with `owner` authority, rather than from a tool call, also saves its
model as the default.

## Example

Request body:

```json
{
  "id": "0b7d2c4e-6f1a-4b3c-9e8d-7a6b5c4d3e2f",
  "name": "Fix the flaky test",
  "content": "Find out why the date test fails on CI"
}
```

Response:

```json
{
  "session": "0b7d2c4e-6f1a-4b3c-9e8d-7a6b5c4d3e2f",
  "receipt": "0b7d2c4e-6f1a-4b3c-9e8d-7a6b5c4d3e2f",
  "message": "0b7d2c4e-6f1a-4b3c-9e8d-7a6b5c4d3e2f"
}
```

## Errors

- `invalid` when the id names a chat started with other input: `Session <id> already exists.`
- `invalid` when a `before_send` hook refuses the message, with the hook's reason, or when the
  start was stopped before the hooks decided.
- `invalid` when `configuration` doesn't fit the catalog: `No model is <provider>/<id>.`,
  `No agent is registered as <agent>.`, or `The configuration is invalid: …` with its issues.
- `unknown` when no workspace was named and the host has no default, when the workspace isn't
  registered, or when `parent` names no session.
- `unavailable` with `isolation: "worktree"` when the workspace isn't in git or its provider has no
  worktrees, and when the host closes before the hooks decide.
- `internal` when a `before_send` hook fails.
