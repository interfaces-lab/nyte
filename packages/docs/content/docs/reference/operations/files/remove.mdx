---
title: files.remove
description: Removes a file, optionally only if it still has the expected version.
---

Permanently removes a file without creating a trash token; `files.restore` cannot undo it. The
built-in local provider also removes folders recursively. With `expect`, removal happens only if
the path still has that version. It answers `saved` with the version it removed, or `stale` when
`expect` doesn't match, with `current` `null` when nothing is there.

## When to call it

After confirming permanent deletion. Prefer [`files.trash`](/docs/reference/operations/files/trash)
for a delete action that offers undo.

## Access

Any principal with `participant` authority. Workspace scope, with the `files` capability.

## Example

Request body:

```json
{
  "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0",
  "path": "src/old-date.ts",
  "options": { "expect": "2c4e6a8b0d1f3a5c7e9b1d3f5a7c9e1b3d5f7a9c1e3b5d7f9a1c3e5b7d9f1a3c" }
}
```

Response:

```json
{
  "kind": "saved",
  "version": "2c4e6a8b0d1f3a5c7e9b1d3f5a7c9e1b3d5f7a9c1e3b5d7f9a1c3e5b7d9f1a3c"
}
```

## Errors

- `unavailable` or `denied` when the workspace doesn't offer files.
