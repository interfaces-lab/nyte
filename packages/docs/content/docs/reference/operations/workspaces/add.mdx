---
title: workspaces.add
description: Adds a folder or other target as a workspace.
---

Registers a target as a workspace. A target already registered answers `exists` with its id.
`projectResources` records whether the folder's project files are trusted; without it the folder
follows a decision saved for it or the nearest folder above.

## When to call it

When the user opens a folder that isn't a workspace yet, usually after
[`workspaces.inspect`](/docs/reference/operations/workspaces/inspect).

## Access

Needs `owner` authority. Host scope.

## Example

Request body:

```json
{
  "target": { "kind": "local", "path": "/Users/ada/code/shop" },
  "options": {
    "projectResources": true,
    "expect": { "identity": "e3a1c9f04b7d2e6a8c5f1b3d9e7a2c4f6b8d0e1a3c5f7b9d2e4a6c8f0b1d3e5a" }
  }
}
```

Response:

```json
{
  "kind": "added",
  "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0"
}
```

Other outcomes: `stale` with the current identity when it differs from `expect`, and `unavailable`
with reason `unsupported` (no provider for the kind) or `unreachable` (the provider can't read it).

## Errors

Only the [errors every operation can raise](/docs/reference/operations#errors); the cases above are outcomes.
