---
title: projects.create
description: Creates a project in a workspace with the models, instructions, skills, MCP servers and shared docs its chats use.
---

Creates a project in a registered workspace and returns it as stored. A project has one coordinator
chat, which is the first top-level chat started in it. `models.coordinator` and `models.agents`
choose the initial models for that chat and its subagents. Either value can be `null` to use the
host's default model, unless the start supplies `configuration.model`; a null agents model does not
inherit the coordinator's model.

`instructions` and the named `skills` join each chat's system prompt. `disabledMcp` names MCP
servers to leave out, and `disabledDocs` names shared docs or context files to leave out. The new
project reaches every client in the host view's `projects`.

## When to call it

From a "New Project" action, before starting the project's first chat with `sessions.start` and its
`project` field.

## Access

Any principal with `participant` authority. Host scope.

## Example

Request body:

```json
{
  "input": {
    "name": "Bug Fix and Polish",
    "workspace": "9dee0b6e-42c2-4ec2-be3a-cf6ff4dcacd2",
    "models": { "coordinator": null, "agents": null },
    "instructions": "Keep fixes small and verify each change.",
    "skills": [],
    "disabledMcp": [],
    "disabledDocs": []
  }
}
```

Response: the project, with `coordinator` null until its first chat starts.

## Errors

- `unknown` when the workspace isn't registered on the host.
- `invalid` when the input doesn't match the schema, such as an empty name.
