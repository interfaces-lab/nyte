---
title: head.read
description: Reads a window of a head's rows at a seq, or what changed in it since a seq the client resumes from.
---

Reads a window of a head's rows at a seq. `window` is `{ tail }`, the last `tail` messages of the
head's path, or `{ from }`, the messages from that one on. The answer carries `seq`, the session seq
the rows are current through, the window's `order` and `leadingPrompt`, every row of the session's
tables the window needs, and the session's live `activation`. A first read is `complete: true`: the
client replaces its tables with it.

To resume after a dropped connection, pass `resume: { seq, from }`, the seq the client's rows are
current through and the first message it holds. The answer then holds only the rows changed after
`seq` and the rows the old window did not cover, with `complete: false`; rows in the client's store
that are in neither the answer's `order` nor its turns are dropped. A `from` the host can't place
on the path any more, or a `seq` older than the log it still holds, answers a complete window.

## When to call it

After [`events.subscribe`](/docs/reference/operations/events/subscribe) on the session's scope,
never before: subscribing first is what keeps a change between the two from being lost.

## Access

Any principal with `participant` authority who can read the session. Session scope. It answers over
HTTP and on the WebSocket.

## Example

Input:

```json
{ "session": "0b7d2c4e-6f1a-4b3c-9e8d-7a6b5c4d3e2f", "head": "main", "window": { "tail": 50 } }
```

Output, with the tables shortened:

```json
{
  "seq": 12,
  "head": "main",
  "order": ["f9b3c8e6-6257-4b24-a875-5f6c9cafb923"],
  "leadingPrompt": null,
  "complete": true,
  "tables": { "messages": { "upsert": [], "drop": [] } },
  "live": { "activation": { "kind": "active" } }
}
```

## Errors

- `unknown` for a session the host doesn't have.

- Capability: none
- Recovery: none
- Wait: no
