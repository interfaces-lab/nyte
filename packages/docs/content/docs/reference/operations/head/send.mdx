---
title: head.send
description: Sends a message to a head and returns its receipt.
---

Sends a message to a head and answers its receipt once the session's `before_send` hooks have
accepted it. The message id is the receipt id. What happens next depends on `delivery`: `steer`
(the default) reaches a live run at its next boundary, `queue` waits for the run to end and starts
the next one, and `attach` joins the next turn without starting one. `steer` and `queue` start a
run when nothing is running.

With `replace`, the message edits an earlier one: the new content takes its place, and the messages
after it leave the head's path while staying in the session's tree. `running` decides whether a live run is stopped (`stop`, the default) or
the edit refused (`refuse`), `abandoned` whether the replaced messages are summarized, and `expect`
makes the edit conditional on the head's revision.

## When to call it

Each time the user sends a message to an existing chat. To start a chat, use
[`sessions.start`](/docs/reference/operations/sessions/start).
[Send messages](/docs/sdk/guides/send-messages) covers delivery, edits and waiting.

Mint `options.id` before the first attempt and send it with every retry: the same id and input
return the first admission instead of sending twice. Then wait with
[`receipt.landed`](/docs/reference/operations/receipt/landed) or
[`receipt.settled`](/docs/reference/operations/receipt/settled).

## Access

Any principal with `participant` authority. Session scope; `head` names the head, `main` for the
chat's own.

## Example

Request body:

```json
{
  "session": "0b7d2c4e-6f1a-4b3c-9e8d-7a6b5c4d3e2f",
  "head": "main",
  "content": "Then add a regression test",
  "options": { "delivery": "queue", "id": "7c1e9a3b-2d4f-4a6c-8e0b-1f3d5a7c9e2b" }
}
```

Response:

```json
{
  "receipt": "7c1e9a3b-2d4f-4a6c-8e0b-1f3d5a7c9e2b",
  "message": "7c1e9a3b-2d4f-4a6c-8e0b-1f3d5a7c9e2b"
}
```

## Errors

- `unknown` when no session has the id, or the session has no such head:
  `Session <id> has no head <head>.`
- `invalid` when the receipt id was used for different input: `Receipt <id> was used for another
command.`
- `invalid` when a `before_send` hook refuses the message, with the hook's reason.
- `invalid` with `replace` when the message it names is still being decided.
- `internal` when a `before_send` hook fails.
