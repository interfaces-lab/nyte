---
title: git.contents
description: Reads a file's contents on both sides of a scope.
---

Reads a file's contents on both sides of a scope: `old` and `new`, each `text`, `truncated` with
its first part when over 1 MiB, `binary`, or `absent`. A renamed file's old side is read at its old
path.

## When to call it

For a side-by-side diff editor, which needs whole files rather than hunks.

## Access

Any principal with `participant` authority. Workspace scope, with the `git` capability.

## Example

Request body:

```json
{
  "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0",
  "path": "src/date.ts",
  "scope": { "kind": "unstaged" }
}
```

Response:

```json
{
  "path": "src/date.ts",
  "old": { "kind": "text", "text": "export const today = () => new Date();\n" },
  "new": { "kind": "text", "text": "export const today = () => new Date(Date.now());\n" }
}
```

## Errors

- `unavailable` outside a repository, or when the workspace doesn't offer git.
