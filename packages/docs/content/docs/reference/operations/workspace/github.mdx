Answers whether the workspace offers GitHub through the host machine's GitHub CLI (`gh`):
`available`, `unsupported` where the environment serves none, `denied` or `unavailable`.

## When to call it

Before showing pull request status for a workspace. Whether `gh` is installed and signed in shows
in [`github.state`](/docs/reference/operations/github/state) and
[`github.account`](/docs/reference/operations/github/account), not here.

## Access

Any principal with `participant` authority. Workspace scope.

## Example

Request body:

```json
{ "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0" }
```

Response:

```json
{ "kind": "available" }
```

## Errors

Only the [errors every operation can raise](/docs/reference/operations#errors). A workspace id the host doesn't have answers
`unavailable` with `retry` `manual` rather than failing.
