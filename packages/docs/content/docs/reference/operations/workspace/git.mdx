---
title: workspace.git
description: Checks whether the workspace offers git.
---

Answers whether the workspace offers git: `available`, `unsupported`, `denied` or `unavailable`,
as [`workspace.files`](/docs/reference/operations/workspace/files) does for files. A workspace
outside a repository can still answer `available`; its `git.status` then answers `none`.

## When to call it

Before showing a source control panel for a workspace.

## Access

Any principal with `participant` authority. Workspace scope.

## Example

Request body:

```json
{ "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0" }
```

Response:

```json
{ "kind": "available" }
```

## Errors

Only the [errors every operation can raise](/docs/reference/operations#errors). A workspace id the host doesn't have answers
`unavailable` with `retry` `manual` rather than failing.
