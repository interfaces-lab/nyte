---
title: operations.describe
description: Describes the operations this host serves, or the ones named, with their access and wire JSON Schemas.
---

Returns the operations this host serves, in table order, each with its summary, kind, authority,
scope, capability, and its input and output as draft 2020-12 JSON Schemas of the wire form. Pass
`names` to describe only those operations, in that order.

## When to call it

When a client builds requests from the table rather than from a pinned SDK, such as a generic
tool caller or a protocol inspector. The answer comes from the connected host's own build, so it
matches that host's version even when the client's differs.

## Access

Any principal with `participant` authority. Host scope. The answer lists every operation, whatever
the caller's authority; calling one still needs its authority.

## Example

Request body:

```json
{ "names": ["session.info"] }
```

Response, with the input and output schemas shortened:

```json
[
  {
    "name": "session.info",
    "summary": "Reads a session's name, state and other details.",
    "kind": "query",
    "authority": "participant",
    "scope": "session",
    "input": { "type": "object", "required": ["session"] },
    "output": { "type": "object" }
  }
]
```

## Errors

- `invalid` when a name in `names` isn't an operation: `No operation is named <names>.`

## Declaration

- Kind: `query`
- Authority: `participant`
- Scope: `host`
- Capability: none
- Recovery: none
- Wait: no

### Input schema

```json
{
  "type": "object",
  "properties": {
    "names": {
      "type": "array",
      "items": {
        "type": "string"
      }
    }
  }
}
```
