Admission decides what queued input may land, and whether it may start model work. User input starts a run. So does a delegate's answer to a request its run authorized, unless that run was stopped or failed.

<Sketch
              title="land, step.ts"

const queued = await pendingIn(session, { head, delivery });

// At a boundary that owes an answer, only leading answers and reports.

const batch = atBoundary

: nextBatch(queued, drain);

const decision = decide(headFor(run), await leadFor(session, batch), agentChanged(run, batch));`}

- `fresh` has no run and `idle` has a terminal one. `live` is any other phase, and `settling` is live with `abortRequested`. A live head is decided only at a `respond` boundary.
- The lead is the batch's first `user` change or authorized `answer`. Without one it is `passive` when any change in the batch is passive, and otherwise the first `report` or unauthorized `answer`.
- `join*` becomes `handoff` when the batch names another agent. Handoff ends the run `done` and leaves the batch pending.
- An authorized answer is a child's answer to a request whose run was neither stopped nor failed, and that no landing has consumed. It starts a continuation that inherits the chain counter, and the landing CAS consumes the authorization.
- On an idle head a `report` or unauthorized `answer` starts nothing. The next run picks it up in its first batch or at its first `respond` boundary. A `passive` lead lands its batch without a model call.
