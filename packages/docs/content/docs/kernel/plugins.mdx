A plugin adds tools, parts, commands, settings and hooks to a session. It is an object with an `id`, checked with `satisfies Plugin` from `@nyte-ai/plugin/core`:

```ts title="~/.nyte/plugins/hello.ts"
import type { Plugin, ToolDefinition } from "@nyte-ai/plugin/core";
import { standard } from "@nyte-ai/schema";
import { Type } from "typebox";

const hello: ToolDefinition<{ name: string }> = {
  name: "hello",
  description: "Greet someone by name",
  parameters: standard(Type.Object({ name: Type.String() })),
  class: () => ({ kind: "custom", label: "hello" }),
  replay: "safe",
  execute: async ({ name }) => ({ content: [{ kind: "text", text: `Hello, ${name}` }] }),
};

export default {
  id: "hello",
  contribute: { tools: [hello] },
} satisfies Plugin;
```

`contribute` holds static items; `activate(api)` adds derived ones through `api.contribute` and runs once per session. `hooks` are installed before `activate`. The plugins in `packages/plugin/src` are written this way.

Plugins load per session. Everything a plugin registers through its api is removed when it deactivates: on a reload, a removal, or the session closing. An `activate` that throws leaves that plugin out with an `Activation failed` issue; the rest of the set loads. Every hook handler runs under a wall-clock budget, and its `signal` fires when the budget runs out or the plugin deactivates.

The budget is 5 s per handler and 300 s for `before_compaction`. Handlers run by ascending `order` (default 0), then in registration order. A decide hook runs as one durable step: `continue` passes on, `modify` replaces the value later handlers see, and the first `reject` or `error` ends the chain. The recorded decision replays when the step runs again.

## Where plugins come from

`sdk.open` takes the host's core plugins as `plugins`, loaded after the built-ins. Exactly one of them provides the environment for each workspace kind. Then the host loads plugin files:

- **Directories.** `~/.nyte/plugins` as `user`, and for a `local` workspace `<path>/.nyte/plugins` as `project`. Each `.ts`, `.mts`, `.js` or `.mjs` file directly in the directory is a plugin, and so is each subdirectory's `index` file. The default export must be a core plugin. Node strips the types, so a `.ts` file uses erasable syntax only.
- **Failures.** A file that does not load is a row on `HostView.plugins` with its path and the error. The other files load, and the host opens.
- **Preflight.** A duplicate id, the reserved ids `models` and `settings`, or a second environment provider of one kind rejects the plugin. A rejected plugin passed to `sdk.open` fails the open with `invalid`. A tool name, setting id or part kind that two plugins contribute is a warning against the later one.
- **Replacement.** `host.plugins.replace(plugins, { session }?)` replaces the host's plugins, or one session's, and reports each as `activated`, `rejected` or `kept-previous`. `host.plugins.check` runs the same preflight and touches nothing. Over a connection both take file paths, which must lie in a directory the host loads.
