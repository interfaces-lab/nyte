title: Shared concepts
description: The rules every SDK call follows for handles, ids, errors, outcomes, retries, revisions and authority.
---

These rules hold across the whole SDK, so the reference pages for
[Connection](/docs/sdk/reference/connection), [Session and Head](/docs/sdk/reference/session) and
[Workspace](/docs/sdk/reference/workspace) don't repeat them.

## Handles bind without I/O [#handles]

Getting a handle by id never touches the network:

- `connection.session(id)` and `connection.workspace(id)`
- `session.head(name)`, `session.run(id)`, `session.receipt(id)` and `session.part(id)`
- `workspace.job(id)`

The handle's methods check that the thing exists when you call them, and throw
`SdkError("unknown")` when it doesn't. Save an id, rebuild the handle after a reload, and call it.

```ts
import { asId } from "@nyte-ai/schema";

const session = connection.session(asId<"session">(savedId));
const info = await session.info();
```

## Ids are typed [#ids]

Ids are strings with a brand, so a `SessionId` can't be passed where a `RunId` is expected. Ids
that come back from the SDK already carry their brand. Wrap one you stored yourself with
`asId<"session">(value)`; the name in angle brackets is the kind of id. Head names are ids too:
`asId<"head">("try-sqlite")`.

## Errors and outcomes [#errors-and-outcomes]

An SDK call ends in one of two ways when it doesn't simply succeed.

**It throws `SdkError`** when the call couldn't be made: bad credentials, no authority, an id that
doesn't exist, invalid input, a lost connection, or a bug in the host. Every `SdkError` has a
`code` to branch on. [Errors](/docs/sdk/reference/errors) lists the codes and what to do about each.

**It returns an outcome** when the call was made and the answer is one of several expected
results. Outcomes are objects with a `kind`, such as `{ kind: "busy", run }` from `heads.merge` or
`{ kind: "unknown-model", model }` from `configure`. TypeScript makes you handle each one.

```ts
import { SdkError } from "@nyte-ai/sdk";

try {
  await connection.session(asId<"session">(savedId)).view();
} catch (cause) {
  if (cause instanceof SdkError && cause.code === "unknown") forget(savedId);
  else throw cause;
}
```

Catch `SdkError` where your app talks to people, and keep its `code`. Wrapping every call in
another result type adds nothing.

## Retrying is safe [#retrying]

Every write that can be retried takes an id. The same id with the same input returns the first
result instead of acting twice:

- `sessions.start({ id })` names the chat, its first message and its receipt.
- `send(content, { id })` names the receipt.

The SDK mints these ids before the request and resends under them after a failure, so most code
never passes one. Pass one to retry across your own process restart. The same id with different
input throws `SdkError("invalid")`.

## Revisions guard concurrent changes [#revisions]

Views and trees carry a `revision`. Pass it back as `expect` to make a change conditional on what
you saw. When the head has moved since, the call changes nothing and tells you:

| Call                                 | When the head moved                       |
| ------------------------------------ | ----------------------------------------- |
| `send(content, { replace, expect })` | The receipt settles `stale`               |
| `move(position, { expect })`         | The receipt settles `stale`               |
| `heads.merge(name, { expect })`      | Returns `stale` with the current revision |
| `heads.remove(name, { expect })`     | Throws `SdkError("stale")`                |

Read again and decide. Other things use the same idea with their own version:
`files.write(path, contents, { expect })` takes a file version, git writes take a git revision, and
`part.update(next, { version })` takes a part version.

## The host builds the views [#views]

The host turns a session's history into rows: messages, turns, parts and each head's state.
`view()` reads them as one `SessionView`. `openHost` keeps them current over a socket, and
`headView` turns a head store's snapshot into the same view, so a client never replays events
itself. After a reconnect, the store resumes from the last change it applied.
[Render a session](/docs/sdk/guides/render-a-session) shows how to draw one.

## Capabilities are values [#capabilities]

A workspace's files, git, GitHub and browser can each be missing. Each is a capability you check
before using:

```ts
const git = await workspace.git();

if (git.kind !== "available") return git.reason;

const status = await git.api.status();
```

Besides `available`, a capability is `unsupported`, `denied` or `unavailable`, each with a
`reason`. [Capabilities](/docs/sdk/reference/workspace#capabilities) explains each kind.

## Authority [#authority]

Each connection belongs to a principal, which holds a set of authorities. Each operation needs one
particular authority:

| Authority     | Covers                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `participant` | Sessions, files, jobs, the browser, reading git and GitHub, listing models and workspaces                               |
| `owner`       | Model logins and accounts, settings, adding and trusting workspaces, MCP, writing git, GitHub sign-in and pull requests |
| `maintenance` | Checking and replacing plugins, and listing, pairing and revoking principals                                            |

The sets don't nest: a principal with only `owner` can't send messages. The `Host` that `sdk.open`
returns has all three. A listener token grants `participant` and `owner` unless the listener says
otherwise. A paired device gets the set passed to `principals.pair`. A call outside the principal's
authority throws `SdkError("denied")`.

`nyte api describe <operation>` and `connection.operations.describe()` show the authority each
operation needs; see the [HTTP API](/docs/sdk/reference/connection#http-api).
