---
title: Entry points
description: Options for sdk.open, host.listen, sdk.connect and openHost, and the helpers the SDK exports beside them.
---

`sdk.open` runs a host in your Node process, and `host.listen` serves it to other processes. From
another process, `sdk.connect` reaches it over HTTP, and `openHost` attaches to its rows over the
host WebSocket.
[Choose an entry point](/docs/sdk/guides/choose-an-entry-point) helps you pick.

| Import                | Has                                                                                                                               |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `@nyte-ai/sdk`        | `sdk.open`, `sdk.connect`, `createSendJournal`, `pagedViews`, `SdkError` and the SDK's types                                      |
| `@nyte-ai/sdk/client` | The same without `sdk.open`, plus [`openHost`](#open-host), its stores and the helpers that read them, so it never loads the host |

In a browser or React Native bundle, `@nyte-ai/sdk` resolves to a build without the host, and its
`sdk.open` rejects with `SdkError("unavailable")`.

## sdk.open [#sdk-open]

```ts
sdk.open(options?: OpenHostOptions): Promise<Host>
```

Starts a host in this Node process and returns it. A `Host` is a
[`Connection`](/docs/sdk/reference/connection) with all three authorities and
[a few more members](/docs/sdk/reference/connection#host). Every option is optional, so
`sdk.open()` works.

| Option             | Default                                                                   | What it sets                                                                    |
| ------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `store`            | SQLite at the path in `NYTE_DB`, else `<home>/.nyte/nyte.db`              | Where sessions live. The host closes a store it opened, not yours               |
| `workspace`        | `{ kind: "local", path: process.cwd() }`                                  | The default workspace, used when `sessions.start` names none                    |
| `models`           | Nyte's model catalog over logins encrypted in the store                   | The models and provider logins                                                  |
| `plugins`          | `[]`                                                                      | Your core plugins                                                               |
| `home`             | `os.homedir()`                                                            | Where `.nyte` lives, with settings, plugins, keys and the store                 |
| `secrets`          | The key in `<home>/.nyte/secret.key`                                      | `{ key() }`, the key that encrypts saved logins                                 |
| `execution`        | `{ kind: "run", coverage: { kind: "all" } }`                              | Who runs the sessions. See [execution](#execution)                              |
| `mcp`              | A hub over `<home>/.nyte/mcp.json` and trusted projects' `.nyte/mcp.json` | The MCP servers chats use                                                       |
| `github`           | The machine's `gh` login                                                  | What `connection.github` serves                                                 |
| `images`           | The host's own image resizer                                              | Shrinks attached images to fit model limits                                     |
| `shell`            | `$SHELL`, else `/bin/sh`                                                  | `() => string \| null`, the login shell terminal jobs start                     |
| `label`            | `"nyte"`                                                                  | The name this process goes by among processes that share the store              |
| `onRevoked`        | None                                                                      | Called when another process sharing the store has taken this one's place        |
| `onStoreMigration` | None                                                                      | Called before the default store migrates existing data, which blocks the thread |
| `pluginImport`     | Node's import with a resolve hook                                         | How plugin files are imported. A Bun host passes its own                        |

The host always loads the first-party plugins and the plugin files in `<home>/.nyte/plugins`. Your
`plugins` come after the first-party ones. One with a first-party plugin's `id` replaces it. One
that provides the `local` environment replaces the default local provider, and then `github` has no
default.

### execution [#execution]

`execution` decides who runs the sessions this host accepts messages for:

| Value                                    | Who runs them                                                                                                         |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `{ kind: "run", coverage }`              | This process. `coverage` is `{ kind: "all" }`, `{ kind: "workspace", workspace }` or `{ kind: "sessions", sessions }` |
| `{ kind: "admit-only" }`                 | Another process. This one stores messages and runs nothing                                                            |
| `{ kind: "dispatch", dispatch(target) }` | Your queue or workflow engine                                                                                         |

With `dispatch`, the host calls your function with `{ session, head }` each time a head has work.
Hand the target to a worker, which calls `host.execution.advance(target)` and acts on the report:

```ts
const report = await host.execution.advance(target);
```

| Report                         | Next step                                                             |
| ------------------------------ | --------------------------------------------------------------------- |
| `continue`                     | Call `advance` again                                                  |
| `waiting` with `until`         | Call again at `until`, or wait for the next dispatch when it's `null` |
| `retry` or `busy` with `until` | Call again at `until`                                                 |
| `idle`                         | Nothing left to do                                                    |
| `fenced`                       | Another process runs this head now. Stop                              |

[Stores and execution](/docs/host/stores-and-execution#execution) covers the modes in use.

### close [#close]

`host.close()` closes the host's listeners, then the host, stops watching plugin files, and closes
the store if the host opened it. `await using host = await sdk.open()` calls it for you.

## host.listen [#host-listen]

```ts
host.listen(options: ListenOptions): Promise<Listener>
```

Serves the host to other processes. Clients reach it with `sdk.connect` or
[`openHost`](#open-host), or through the [HTTP API](/docs/sdk/reference/connection#http-api).
[Serve a host](/docs/host/serve) walks through auth, pairing and origins.

| Option         | What it does                                                                                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `transport`    | `{ kind: "http", hostname?, port? }` binds a TCP port, by default on `127.0.0.1` and a free port. `{ kind: "socket", path }` binds a Unix socket at `path` with owner-only permissions. `{ kind: "fetch" }` binds nothing; call `listener.fetch(request)` from your own server |
| `auth`         | `{ kind: "token", token, authority? }` or `{ kind: "custom", authorize(request) }`                                                                                                                                                                                             |
| `origins`      | Browser origins allowed to call it, such as `https://app.example.com` or `https://*.example.com`                                                                                                                                                                               |
| `execution`    | `{ kind: "run", coverage }` (default: all sessions) or `{ kind: "admit-only" }`                                                                                                                                                                                                |
| `maxBodyBytes` | The largest request body. Default 8 MiB                                                                                                                                                                                                                                        |
| `identity`     | `{ id, sign(nonce) }`, the signed answer that lets `connect({ expect })` check it's this host. `sdk.open` supplies one                                                                                                                                                         |
| `describe`     | `() => { name, platform, version }`, served at `GET /.nyte/describe`. `sdk.open` supplies one                                                                                                                                                                                  |
| `before`       | `(request) => Response \| undefined`. Runs first; return a response to answer the request yourself                                                                                                                                                                             |

A `token` must be at least 16 characters. It grants participant and owner authority unless you pass
`authority`. Grant `maintenance` only to a token your own processes use, never one you hand to
someone else.

`custom` auth maps each request to `{ principal, authority }`, or to `{ deny: "unauthorized" }` or
`{ deny: "forbidden" }`.

`https://*.example.com` allows every subdomain of `example.com`, but not `example.com` itself.

The `http` and `socket` transports also serve the
[host WebSocket](/docs/sdk/reference/connection#websocket) at `/.nyte/ws`, which `openHost` opens.
`fetch` serves HTTP only. Operations marked `local`, such as `host.execution.pause`, answer only on
the `socket` transport.

The `Listener` it returns has:

| Member                | What it does                                                                   |
| --------------------- | ------------------------------------------------------------------------------ |
| `address`             | The URL it listens on, the socket's path, or `null` with the `fetch` transport |
| `fetch(request)`      | Answers one HTTP request                                                       |
| `disconnectClients()` | Drops every open request, stream and WebSocket. Clients reconnect              |
| `close()`             | Disconnects clients and stops listening                                        |

## sdk.connect [#sdk-connect]

```ts
sdk.connect(options: ConnectOptions): Promise<Connection>
```

Connects to a host over HTTP and resolves once the host has sent its first view, so a wrong URL or
token fails here rather than on the first call.

| Option        | What it does                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------- |
| `url`         | The listener's address                                                                        |
| `credentials` | How to sign in. See below                                                                     |
| `expect`      | `{ hostId }`. Throws `SdkError("stale")` when a different host answers                        |
| `journal`     | Where unsent messages wait. Default: in memory. See [createSendJournal](#create-send-journal) |
| `fetch`       | `(url, init?) => Promise<Response>`, used instead of the global `fetch`                       |

`credentials` is one of:

- `{ kind: "token", token }` for a listener token, or a device token from pairing.
- `{ kind: "pairing", code }` for a code from `principals.pair`. After connecting,
  `connection.credential` holds the device token to save.
- `{ kind: "custom", headers() }` to compute request headers yourself, for a listener with
  `custom` auth.

With `expect`, `connect` first asks the host to sign a random challenge and checks the signature
and host id, then checks the id again on the first view. A host that doesn't answer the challenge
is checked on the first view alone.

## createSendJournal [#create-send-journal]

```ts
createSendJournal(): RequestJournal
```

The in-memory journal `connect` uses when you pass none. Messages in it survive a dropped
connection but not a restart. To keep them across restarts, pass your own `RequestJournal`:

```ts
interface RequestJournal {
  load(): Promise<readonly JournalEntry[]>;
  put(entry: JournalEntry): Promise<void>;
  remove(id: ReceiptId): Promise<void>;
}
```

`connect` calls `load` once and resends what it returns. `send` calls `put` before the request. It
calls `remove` once a view of the head shows the message, or when the send fails with an error it
doesn't retry. A `JournalEntry` is plain JSON, so any key-value store works.

## pagedViews [#paged-views]

```ts
pagedViews<V>(
  head: { watch(options?: ViewOptions): AsyncIterable<V> } & Pick<Head, "history">,
  options?: ViewOptions,
): PagedViews<V>
```

Reads the views the `watch` you pass yields and keeps the older messages you load at the front of
each one. A `Head` has no `watch`, so pass a function that returns your own views, such as views
built from a [head store](#open-host), with the head's `history`. `PagedViews` is an
`AsyncIterable<V>` with one more method:

- `earlier(limit)` loads up to `limit` messages before the oldest one shown through `head.history`,
  and resolves with how many came: `0` once the chat's first message is shown. A call while one is
  loading waits for it.

If the head moves past the loaded pages, the next view drops them. Iterate it once.
[Load older messages](/docs/sdk/guides/render-a-session#load-older-messages) shows it in use.

## openHost [#open-host]

```ts
openHost(address: string, options: HostOptions): HostConnection
```

From `@nyte-ai/sdk/client`. Opens the [host WebSocket](/docs/sdk/reference/connection#websocket)
at `address` and keeps the rows you attach to current, the way Nyte's own clients read a host.
Every caller with the same address shares one connection, and a later caller's options are ignored.
`release()` lets go of it, and the last release closes the socket.

| Option        | What it sets                                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `credentials` | `{ kind: "token", token }` or `{ kind: "custom", headers() }`, as for `sdk.connect`. A pairing code goes through `sdk.connect` first   |
| `client`      | `{ kind, name, version }`, what other clients see for this one. `kind` is `app`, `tui`, `cli`, `agent` or `other`                      |
| `socket`      | How to open the WebSocket. The default sends the credentials as headers, which Node and Bun accept. In a browser pass `ticketSocket()` |
| `fetch`       | Used instead of the global `fetch` to tell a refused credential from a host that is down                                               |
| `online`      | `() => boolean`, asked before each dial. `false` skips the dial and leaves `health` `blocked` with reason `offline`                    |

`ticketSocket({ fetch? })` trades the credentials for a one-use ticket at `POST /.nyte/ws/ticket`,
then opens the socket with `?ticket=`.

A `HostConnection` has:

| Member                                     | What it does                                                                                                                                                       |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `head(session, head, { tail })`            | A store of one head's last `tail` messages and the rows they need                                                                                                  |
| `part(session, part)`                      | A store of one part by id, wherever it sits in the session, kept current from the session's changes                                                                |
| `directory(window?)`                       | A store of the `sessions` table. `window` is `{ parents?, limit? }`, as for `sessions.read`                                                                        |
| `clients()`                                | A store of the connected clients, a `Map` of `ClientRow` by client id                                                                                              |
| `text(listener)`                           | Opens the text channel and calls `listener` with each `TextUpdate`. Returns the unsubscribe                                                                        |
| `call(name, input)`                        | Calls any query, command or receipt operation over the socket                                                                                                      |
| `perform(client, action, input, options?)` | Asks another client to perform an action it declared, with `client.perform`. `options` is `{ timeoutMs? }`                                                         |
| `offer(action, handler)`                   | Declares `{ name, summary, input }` in this client's hello, reconnecting to do so, and answers each request with `handler(input, requester)`. Returns the disposer |
| `health`                                   | A store of `connecting`, `open`, `retrying` with the next attempt's time, or `blocked` with reason `auth`, `version` or `offline`                                  |
| `retry()`, `wake()`                        | Dials again now, with the backoff reset, when the connection is `retrying` or `blocked`                                                                            |
| `hostId`                                   | The host's id once its welcome arrived, else `null`                                                                                                                |
| `release()`                                | Lets go of the connection                                                                                                                                          |

Each store has `subscribe(listener)`, which returns the unsubscribe, `snapshot()` and `close()`.
The head, part and session stores also have `freshness()`: `fresh` with the `seq` their rows are current
through, or `stale` while the socket is down or a read failed. A stale store keeps its rows and
resumes from its seq once the socket is back.

- A head, part or session store's `snapshot()` is `null` before the first read.
- A part store's snapshot is `{ part }`: the part's row, with its `placement`, or `null` when the
  session has no such part. It reads the part again after the socket is back, instead of resuming
  from its seq.
- A head store's snapshot holds the head's `order`, `leadingPrompt`, `activation`, `catalog`, and
  `rows`, a `Map` per table keyed by row id.
- A session store's snapshot holds the listed `ids` in order, each one's `SessionInfo` in `rows`,
  and every session's `activation` by id in `activations`.

These helpers come with it:

| Helper                                   | What it does                                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `headView(snapshot)`                     | Builds a `HeadView`, a `SessionView` without `seq`, from a head store's snapshot               |
| `streamText(texts, update)`              | Keeps the latest streamed text and tool progress of each part in a `StreamedText` map          |
| `withStreamedText(view, texts)`          | Lays the streamed text over a `HeadView`                                                       |
| `unsentSends(connection, session, head)` | The sends still in an `sdk.connect` connection's journal. `lay(view, seq)` adds them to a view |

[Render a session](/docs/sdk/guides/render-a-session) shows a head store in use.
