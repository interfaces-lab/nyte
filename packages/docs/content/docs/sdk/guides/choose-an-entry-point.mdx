---
title: Choose an entry point
description: Run the host in your process with sdk.open, or reach one elsewhere with sdk.connect.
---

The host is the process that runs the agent and stores its sessions. Decide where it runs, and the
entry point follows:

| You are writing                                    | Use                                      |
| -------------------------------------------------- | ---------------------------------------- |
| A script, server or CLI that runs the agent itself | `sdk.open` from `@nyte-ai/sdk`           |
| A browser or mobile app                            | `sdk.connect` from `@nyte-ai/sdk`        |
| A Node client of a host that runs elsewhere        | `sdk.connect` from `@nyte-ai/sdk/client` |

`sdk.open` returns a `Host` and `sdk.connect` returns a `Connection`. A `Host` is a `Connection`
with a few extra members, so code written against `Connection` works with both. Starting with
`sdk.open` and moving the host into its own process later changes one line.

## Run the host in your process

```ts title="host.ts"
import { sdk } from "@nyte-ai/sdk";

const host = await sdk.open();
const { receipt } = await host.sessions.start({ content: "Explain this repository" });

await receipt.settled();
await host.close();
```

`sdk.open` needs Node 26.4 or later. Every option has a default:

| Option      | Default                                                                                             |
| ----------- | --------------------------------------------------------------------------------------------------- |
| `store`     | SQLite at `<home>/.nyte/nyte.db`, or at `NYTE_DB` when it is set. The host closes it when it closes |
| `workspace` | The local folder `process.cwd()`                                                                    |
| `models`    | Nyte's model catalog, with credentials encrypted in the store                                       |
| `plugins`   | None. The built-in plugins and `<home>/.nyte/plugins` load either way                               |
| `home`      | `os.homedir()`                                                                                      |

[Entry points](/docs/sdk/reference/entry-points) lists the rest.

Pass your own store to keep the agent's data apart from Nyte's. A store you pass stays yours, so
close it after the host:

```ts title="host.ts"
import { sqliteStore } from "@nyte-ai/host";
import { sdk } from "@nyte-ai/sdk";

const store = sqliteStore({ path: "./agent.db" });
const host = await sdk.open({
  store,
  workspace: { kind: "local", path: "/Users/me/project" },
});

// ...

await host.close();
await store.close();
```

In a local workspace, the agent's tools run in that folder without asking by default.
`host.settings.apply("permissions", "ask")` makes them ask first, and
[Answer approvals and questions](/docs/sdk/guides/answer-approvals-and-questions) shows how to
answer. The folder's own instructions and plugins wait until you
[trust the folder](/docs/build/composition#the-folder-it-works-in). For a host with no folder at all,
use `chatOnlyProvider()` from `@nyte-ai/host/providers` as in
[Chat without a folder](/docs/sdk/examples#chat-without-a-folder).

## Serve it to other processes

`host.listen` puts the same host on HTTP:

```ts title="host.ts"
const listener = await host.listen({
  transport: { kind: "http", port: 8787 },
  auth: { kind: "token", token: process.env.NYTE_TOKEN ?? "" },
  origins: ["https://app.example.com"],
});

console.log("Listening on", listener.address);
```

- It binds `127.0.0.1` unless you pass a `hostname`.
- It throws `SdkError("invalid")` for a token shorter than 16 characters.
- `origins` lists the browser origins allowed to call it. `https://*.example.com` allows every
  subdomain of `example.com`, but not `example.com` itself.
- `host.close()` closes its listeners first.

Behind your own sign-in, `auth: { kind: "custom", authorize }` maps each request to a principal and
the authority it holds, or denies it.

## Connect from another process

```ts title="client.ts"
import { sdk } from "@nyte-ai/sdk/client";

const connection = await sdk.connect({
  url: "https://agent.example.com",
  credentials: { kind: "token", token: process.env.NYTE_TOKEN ?? "" },
});
```

`connect` resolves once the host has answered, so a bad URL or token fails here rather than on the
first call. In a browser or React Native, import from `@nyte-ai/sdk`. Its build for those platforms
has no host code, and `sdk.open` there throws `SdkError("unavailable")`. `openHost`, which attaches
to a host's rows over its socket, comes from `@nyte-ai/sdk/client` on every platform.

The other options:

| Option    | What it does                                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------------------------------- |
| `expect`  | Checks that the host answering is the one you expect. See below                                                        |
| `journal` | Keeps unsent messages across restarts. See [Send messages](/docs/sdk/guides/send-messages#retries-are-already-handled) |
| `fetch`   | Replaces the global `fetch`, for a proxy or a test                                                                     |

The listener token grants full access to the host. Keep it on machines you control, and never put it
in a `VITE_*` or `NEXT_PUBLIC_*` variable.

### Give each device its own credential

Pairing gives a device its own token, so you never copy the listener token onto it. The host mints a
one-time code, and the device trades it for a token. Revoking that device later leaves every other
credential working.

```ts tab="host.ts"
import { sdk } from "@nyte-ai/sdk";

const host = await sdk.open();
const { code } = await host.principals.pair({ authority: new Set(["participant"]) });

console.log("Pairing code:", code);
```

```ts tab="device.ts"
import { writeFile } from "node:fs/promises";
import process from "node:process";
import { sdk } from "@nyte-ai/sdk/client";

const connection = await sdk.connect({
  url: "https://agent.example.com",
  credentials: { kind: "pairing", code: process.argv[2] ?? "" },
});

await writeFile("credential.json", JSON.stringify(connection.credential));
```

Run `host.ts`, then `node device.ts <code>` on the device. After pairing, `connection.credential` is
`{ kind: "token", token }`. Pass it as `credentials` next time. `pair` also returns `expiresAt`, when
the code stops working.

`host.principals.list()` lists the principals that can connect, paired devices among them.
`host.principals.revoke(id)` revokes one and closes its live connections.

### Check which host answered

Pass `expect` with a host id you saved earlier. `connect` throws `SdkError("stale")` when a different
host answers at that URL, for example after the machine was reinstalled.

```ts
import { asId } from "@nyte-ai/schema";

const connection = await sdk.connect({
  url: "https://agent.example.com",
  credentials: { kind: "token", token },
  expect: { hostId: asId<"host">(savedHostId) },
});
```

`connection.hostId` is the id to save.

### Show the connection's state

The SDK reconnects on its own when the network drops. `connection.watch()` yields the host's view
on every change, and its `link` says whether the connection is up:

```ts
for await (const host of connection.watch()) {
  if (host.link.kind === "reconnecting")
    console.log(`Reconnecting (attempt ${host.link.attempts})`);
  if (host.link.kind === "closed") console.log(`Disconnected: ${host.link.reason}`);
}
```

`link.kind` is `connected`, `reconnecting` or `closed`. A closed link's `reason` is `client` after
`connection.close()`, `revoked` when the host stopped accepting the credential, or `host-gone` when a
different host now answers at the URL. A closed connection doesn't reopen. Call `connect` again.

The connection `openHost` returns reports its socket in `health`, a store with `subscribe` and
`snapshot`. The snapshot's `kind` is `connecting`, `open`, `retrying` with the `attempt` and `at`,
the time it dials again, or `blocked` with a `reason` of `auth`, `version` or `offline`. While it
is `retrying` or `blocked`, `retry()` dials again at once.

## What differs between the two

A `Host` has these members that a `Connection` doesn't:

- `listen` serves the host over HTTP, on a Unix socket, or as a fetch handler.
- `inspect(session)` reads a session's stored records and events, for debugging.
- `execution` lets you drive sessions yourself, and `pause` and `resume` model requests, for example
  while the machine sleeps.
- `plugins.replace` accepts plugin objects as well as plugin files.

Everything else, from `sessions` to `models`, behaves the same over the network. The difference you
will notice is authority. A connection with the listener token gets participant and owner authority,
unless the listener's `auth.authority` says otherwise. A paired device gets what `pair` granted, so
a device paired with `participant` can chat but can't sign in to models or change settings.
