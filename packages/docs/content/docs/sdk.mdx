Create one `Nyte` from a store, stream function, model catalog, and plugins.

`messages.send` writes to the inbox but does not start a run. The process that called `attach()` runs
the message. Without one, `runs.wait` never returns.

## Two entries

| Entry                 | Imports                                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@nyte-ai/core`       | `createNyte`, the wire data types, and `MAIN`. `CursorExpired`, the operation table, envelopes, and SSE codec come from `@nyte-ai/protocol`. Projections come from `@nyte-ai/client`. |
| `@nyte-ai/core/store` | `SqliteStore`, `WorkerStore`, and the `Store` contract. `WorkerStore` runs SQLite in a worker thread for hosts that also render. Only hosts import this entry.                        |

Author plugins through `@nyte-ai/core/plugins`. `@nyte-ai/plugin` re-exports it and adds `define`
for local TUI plugins. Nyte's clients share one database per workspace at
`~/.nyte/workspaces/<path-hash>/sessions.db`, the path `workspaceStorePath` returns.

```ts title="host.ts"
import process from "node:process";
import { createModels, FileCredentialStore, openaiCodexProvider } from "@nyte-ai/ai";
import { createNyte, MAIN } from "@nyte-ai/core";
import { systemPromptPlugin, toolsFsPlugin } from "@nyte-ai/core/plugins";
import { SqliteStore } from "@nyte-ai/core/store";
import { workspaceStorePath } from "@nyte-ai/host";

const cwd = process.cwd();
const store = new SqliteStore(await workspaceStorePath(cwd));
const models = createModels({ credentials: new FileCredentialStore() });
models.setProvider(openaiCodexProvider());
const model = models.getModel("openai-codex", "gpt-5.6-luna");
if (model === undefined) throw new Error("model unavailable");

const nyte = await createNyte({
  store,
  streamFn: (requested, context, options) => models.streamSimple(requested, context, options),
  models,
  model,
  drain: "one",
  plugins: [systemPromptPlugin(), toolsFsPlugin()],
  env: { cwd },
});

const detach = nyte.attach();
const session = await nyte.sessions.create();

const printer = (async () => {
  for await (const event of nyte.watch({ sessionId: session.sessionId, live: true })) {
    if (event.kind === "text_delta") process.stdout.write(event.delta);
  }
})();

await nyte.messages.send({
  sessionId: session.sessionId,
  head: MAIN,
  content: "list the TypeScript files here",
});
await nyte.runs.wait({ sessionId: session.sessionId });

detach();
await nyte.close();
await store.close();
```

`drain` defaults to `"one"`; `"all"` lands the whole selected delivery. `head` defaults to `MAIN`.

## The client loop

Open with `sessions.snapshot`, draw it, then watch from its `seq`. `appendTranscriptCommit` returns
`undefined` when the head moved, and `watch` throws `CursorExpired` for a cursor below the event
floor. Both mean take a new snapshot.

```ts title="follow.ts"
import { appendTranscriptCommit } from "@nyte-ai/client";
import type { TranscriptState } from "@nyte-ai/client";
import type { Nyte } from "@nyte-ai/core";
import { CursorExpired } from "@nyte-ai/protocol";
import type { SessionId } from "@nyte-ai/protocol";

async function follow(
  sdk: Nyte,
  sessionId: SessionId,
  draw: (transcript: TranscriptState) => void,
): Promise<void> {
  for (;;) {
    const snapshot = await sdk.sessions.snapshot({ sessionId });
    if (snapshot === undefined) return;
    let transcript: TranscriptState = { items: snapshot.transcript, tip: snapshot.tip };
    draw(transcript);

    let refold = false;
    try {
      for await (const event of sdk.watch({ sessionId, afterSeq: snapshot.seq })) {
        if (event.kind !== "commit" || event.head !== snapshot.head) continue;
        const next = appendTranscriptCommit(transcript, event.item);
        if (next === undefined) {
          refold = true;
          break;
        }
        transcript = next;
        draw(transcript);
      }
    } catch (cause) {
      if (!(cause instanceof CursorExpired)) throw cause;
      refold = true;
    }
    if (!refold) return;
  }
}
```

`watch({ afterSeq })` replays retained events, emits `synced`, then stays live. `live: true` skips
replay. Snapshots include `pending`, `run`, and `context`.

## Sends go through an outbox

Assign a key before sending, show the message locally as `sending`, and reuse the key on every
retry. `queued` and `duplicate` both mean the store holds the message.

```ts title="outbox.ts"
async function submit(
  sdk: Nyte,
  sessionId: SessionId,
  content: string,
  sleep: (ms: number) => Promise<void>,
): Promise<string> {
  const key = crypto.randomUUID();
  for (let attempt = 1; ; attempt += 1) {
    try {
      const receipt = await sdk.messages.send({ sessionId, content, key });
      return receipt.change;
    } catch {
      await sleep(Math.min(10_000, 250 * 2 ** (attempt - 1)));
    }
  }
}
```

## The inbox

| Delivery | Lands                                                   |
| -------- | ------------------------------------------------------- |
| `steer`  | At the next response boundary, or when the head is idle |
| `next`   | Only when the head is idle                              |

`messages.send` defaults to `delivery: "next"`.

`messages.redeliver` changes a pending item's `delivery`. Pass `content` to edit it and `before` to
reorder it. Omit `before` to keep its position, or pass `null` to move it last. Items from the first
changed position on get new change IDs. `messages.cancel` withdraws one, or returns `landed` if it
landed first.

## Runs

| Operation      | Outcome                                                                                            | Use                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `runs.wait`    | `idle` \| `waiting { runId }` \| `cancelled`                                                       | Block until the head is free, a tool parks, or the caller cancels.        |
| `runs.reply`   | `signalled` \| `not_waiting` \| `not_found`                                                        | Answer the exact parked generation by `callId` and `waitId`.              |
| `runs.abort`   | `requested { runId }` \| `not_running`                                                             | Stop the live run. What was already said is kept.                         |
| `runs.compact` | `compacted { commit }` \| `aborted` \| `nothing_to_compact` \| `busy { run }` \| `failed { code }` | Write one checkpoint now, with the branch's own model and thinking level. |

`runs.compact`'s `failed` carries a `code` of `internal`, `inactive`, `busy`, `conflict`, or
`fenced`. Switch on the code, not the message.

```ts
const outcome = await sdk.runs.wait({ sessionId });
if (outcome.kind === "waiting") {
  const snapshot = await sdk.sessions.snapshot({ sessionId });
  const parked = snapshot?.parked?.find((call) => call.selection !== undefined);
  if (parked !== undefined) {
    await sdk.runs.reply({
      sessionId,
      runId: parked.runId,
      callId: parked.callId,
      waitId: parked.waitId,
      reply: { choices: ["blue"] },
    });
  }
}
const compacted = await sdk.runs.compact({ sessionId, customInstructions: "keep file paths" });
```

A parked selection needs no live process to answer. If the same call parks again, its new `waitId`
tells clients to clear picks and show the replacement.

`runs.context` returns token use. `runs.diff` returns the per-run file diff from commit trees when
the host has a VCS backend, or from `file_patch` facts otherwise. `runs.revert` restores the files
the run changed to their state at its start.

## Jobs

Core tracks `bash` commands as jobs, including ones started with `background: true`. Children are
sessions, not jobs. List them with `sessions.list({ parent })`.

Background or cancel running work by its job ID, not its run ID.

```ts title="jobs.ts"
import type { Nyte, SessionId } from "@nyte-ai/core";

async function backgroundWork(sdk: Nyte, sessionId: SessionId) {
  const jobs = await sdk.jobs.list({ sessionId, head: "main" });
  const job = jobs.find((job) => job.phase.kind === "running" && !job.isBackgrounded);
  if (job === undefined) return;
  return sdk.jobs.background({ sessionId, jobId: job.id });
}

async function cancelJob(sdk: Nyte, sessionId: SessionId, jobId: string) {
  return sdk.jobs.cancel({ sessionId, jobId });
}
```

`jobs.background` and `jobs.cancel` return `applied`, `finished`, or `not_found`. Backgrounding
keeps the work running and releases the parked parent call. Cancelling affects only that job.
`runs.abort` cancels the run's command jobs and parked waits, but not its children or user jobs. These
controls work while the parent waits.

A run's job has `origin: { kind: "run", runId, callId }`, and a `jobs.start` job has
`{ kind: "user" }`. `isBackgrounded` stays true after completion. Phases are `running`, `completed`,
`failed`, `cancelled`, and `interrupted`. Output keeps the last 50,000 characters. Jobs are not in the
session snapshot. Read them with `jobs.list`, which covers every head unless you filter.

Job records and output are durable, but work stops with its host and becomes `interrupted` without
rerunning. A finished background job lands once on its originating head as a `completion` commit with
`steer` timing. `runs.abort` drops a completion unless its delivery has started.

On an idle head, only user input or a delegate's answer starts a run. The answer continues the run
that asked, once, unless that run was stopped. Clients do not submit completion messages.

Children inherit workspace trust and cannot use tools marked `availability: "foreground"`.

## Heads

`heads.move` moves a head, `main` by default, and keeps abandoned branches. Moving to a user message
puts the head on its parent and returns the message in `restored`. With `summary`, any abandoned
commits become one `summary` commit on the target. A model failure returns `failed` without moving
the head.

```ts
const moved = await sdk.heads.move({
  sessionId,
  to: user.commit,
  expect: snapshot.tip,
  summary: { customInstructions: "what the abandoned attempt learned" },
});
if (moved.kind === "moved") {
  void moved.restored?.content;
  void moved.summary;
}
```

The outcomes are `moved`, `busy { run }`, `moved_since { tip }`, `not_found`, and `failed`. `expect`
rejects a stale view with `moved_since`. `heads.create` stacks a head on another head or commit.
`heads.merge` fast-forwards a current stacked child into its parent.

## Events a client folds

Every event has `seq`. Keep the last applied value as the cursor.

| Kind                                    | Fold                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `commit`                                | `appendTranscriptCommit`; `undefined` means re-snapshot.                                         |
| `head_moved`                            | The tip the next commits will follow. Clear any provisional text.                                |
| `run`                                   | The head's `RunInfo`. A terminal phase drops the run's overlay.                                  |
| `job`                                   | Upsert `event.job` by job ID, or refresh `jobs.list`.                                            |
| `queued` / `landed` / `queue_cancelled` | The pending gutter. Pending is also a store read, never client memory.                           |
| `text_delta` / `reasoning_delta`        | Provisional text keyed by `(runId, attempt, index)`; the commit settles it.                      |
| `tool_progress` / `effect`              | A call's live output and durable state: intent, waiting, expired, signal, result.                |
| `stack` / `fact` / `deleted`            | Head metadata, a small session value, the session going away. A deleted fact carries no `value`. |
| `compaction`                            | Checkpoint work in flight on that head; `compaction: null` means it ended.                       |
| `config_queued`                         | A configuration choice joined the queue before anything landed.                                  |
| `activation_changed`                    | Host-local activation state, replayed once per watch and not ordered by `seq`.                   |
| `synced`                                | Replay is over; what follows is live.                                                            |
| `diagnostic` / `plugins_changed`        | A notice to show, and the plugin list to re-read.                                                |
| `notification` / `status_changed`       | A plugin asking for attention, and the status items to show beside the model.                    |

A user run has `origin: { kind: "user" }` and uses its `runId` as `root`. A continuation origin
names the child session and request as `{ kind: "commit", oid }` after landing or
`{ kind: "change", oid }` if stopped first. It keeps the requesting run's root, which bounds response
attempts across the chain. Retry phases carry `retry { at, retries, failure }`; `retries` counts
consecutive retries.

A compaction checkpoint arrives as a `commit`; `compaction` reports progress only.

## What the host still owns

1. Build `Models`, register providers, and resolve a credential.
2. Gate project plugins on workspace trust with `WorkspaceStore` from `@nyte-ai/host`. Grants live in
   `~/.nyte/workspaces.json`, and a directory inherits trust from its nearest trusted ancestor. Print
   mode never grants trust.
3. Resolve plugins with `resolveHostPlugins` from `@nyte-ai/host`. Local plugins use
   `plugins/<id>/index.ts` for session behavior and `plugins/<id>/tui.ts` for the terminal.
   Global roots load before trusted project roots, and a later plugin replaces an earlier one with the same ID.
   Watch plugin, context, skill and manifest inputs with `watchPluginDirectories` from
   `@nyte-ai/host/plugins`. A failed reload keeps the active set. `setPlugins` returns `applied`,
   `queued`, or `rejected`. A queued replacement waits for the current response and its tool calls,
   parked calls included, to finish.
4. Pass that list, `streamFn`, `store`, and `env.cwd` into `createNyte`, or pass `resolveActivation`
   to load plugins the first time a session activates.
5. Call `attach()` in the process that should run tools.
6. Pass `workspace.vcs`, such as `createGitVcs` from `@nyte-ai/host`, so `nyte.workspace.vcs`
   answers snapshot, diff, contents, log, refs, stage, discard, commit, createBranch, and push for
   the session's directory. Without it, reads answer empty and writes answer `failed`. A mutation's
   `expect` rejects a moved tree. It is a public digest, so it does not prove the client read the
   tree.

Trust is not a sandbox or per-call approval. It loads project plugins and unrestricted filesystem
tools.

Pass plugin objects directly: `plugins: [systemPromptPlugin(), toolsFsPlugin()]`. Reusing the same
object keeps its setup; a new object with the same ID replaces it. File-loaded plugins use the
loader's content revision, so unchanged scans keep the active setup and `/reload` forces a fresh load.

Agents are plugin contributions. See [Agents](/docs/design#agents).
