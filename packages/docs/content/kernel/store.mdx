Git does not fit everywhere. A commit has exactly one context parent, because model context is linear. There is no worktree; a client reads at any commit. The SDK carries a stale branch forward with a summary commit instead of rebasing. The event log can be trimmed, so a cursor can expire.

## One publish

1. The runner puts the new objects. Nothing names them yet, so no reader can see them.
2. It calls `refs.update` with its lease. A stale lease answers `fenced` before any ref is compared&nbsp;<Src path="sqlite.ts" line={653} />.
3. Every ref must still hold its `from`. One mismatch answers `conflict` and writes nothing.
4. Each moved ref appends a `ref` event in the same transaction, and watchers wake when the transaction commits.
