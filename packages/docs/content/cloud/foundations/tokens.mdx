Components paint with `--nyte-*` custom properties only. The compiled stylesheet declares every
token on `:root`, so loading it is enough.

```css
@import "@nyte-ai/ui/ui.css";
```

An app that compiles StyleX itself gets the same declarations from the compiler, and reads the
tokens through typed constants.

```ts
import { t } from "@nyte-ai/ui/vars.stylex";
```

```ts
const styles = stylex.create({
  note: { color: t.contentSecondary, borderRadius: t.radius6 },
});
```

## Layers

The tokens follow Notion Calendar's layered system.

| Layer             | Tokens                                                   | What it holds                                                       |
| ----------------- | -------------------------------------------------------- | ------------------------------------------------------------------- |
| Ramps             | `--nyte-{hue}-{step}`, `--nyte-translucent-…`            | Ten hues in twenty steps, 0 to 150, in `lab()`                      |
| Theme             | `--nyte-theme-{step}`, `--nyte-theme-translucent-…`      | The ramp a scope paints with, gray by default                       |
| Roles             | `--nyte-content-*`, `--nyte-border-*`, `--nyte-bg-*`     | What each step paints: text, edges, and surfaces                    |
| Component colours | `--nyte-composer-*`, `--nyte-popup-material` …           | Nyte's own surfaces, built on the roles                             |
| Size primitives   | `--nyte-spacing-*`, `--nyte-sizing-*`, `--nyte-radius-*` | Notion Calendar's length scale                                      |
| Component sizes   | `--nyte-btn-*`, `--nyte-input-*`, `--nyte-row-*` …       | Control measurements over the primitives, with a coarse-pointer box |

A component names a role, never a ramp step, unless the colour must stay the same everywhere,
such as a chart series or a status dot. From `@nyte-ai/ui/vars.stylex`, `t` holds the roles,
component colours, shadows, type, radius, and motion, and `ramp` holds the opaque steps. The
component sizes come from `@nyte-ai/ui/schema.stylex` as `button`, `input`, `switchControl`,
`checkbox`, `row`, and `menu`.

## Light and dark

Roles resolve by `color-scheme`: a role is a `light-dark()` pair, a single step both modes share,
or a colour derived from another role, so a component follows the `color-scheme` in effect rather
than a class. The package sets no `color-scheme`, so set one. The desktop sets it from
`data-display-mode` on `<html>`.

```css
:root {
  color-scheme: light;
}

:root[data-display-mode="dark"] {
  color-scheme: dark;
}
```

A subtree can take the other appearance on its own with `color-scheme` on any ancestor.

## Scopes

A scope paints a subtree in one hue. It swaps the theme layer and re-declares the roles from it,
which is why both halves travel together: a custom property inherits its computed value, so a
role resolved above the scope would stay gray.

```ts
import { intent, surfaceTheme } from "@nyte-ai/ui/surface-theme";

<div {...stylex.props(surfaceTheme.blue, styles.card)} />;
<div {...stylex.props(intent.danger, styles.banner)} />;
```

`intent.primary`, `success`, `warning`, and `danger` are the blue, green, yellow, and red scopes.
Checked controls and filled buttons paint inside `intent.primary`. The control roles
(`bg-control`, `border-control`, `content-on-control`) keep their neutral value in every scope, so
an empty checkbox stays gray inside one. Menus, popovers, dialogs, tooltips, and preview cards take
a `tint` prop, and `toastTint()` scopes a single toast.

`surfaceTheme.custom` builds a hue from Notion Calendar's template ramp at
`--nyte-custom-hue` and `--nyte-custom-chroma-scale`. The desktop puts it on `<html>` as the
workspace tint.

## Overriding

Override a ramp step or a role on an ancestor. A scope re-declares every role on the element that
starts it, so a role overridden on `:root` holds only outside scopes. To recolour a subtree, give
it a scope.

```css
.preview {
  color-scheme: dark;
  --nyte-bg-base: #101014;
}
```

## Roles

Content is text and icons. Text that must be read uses `content-secondary` or stronger;
`content-tertiary` is for placeholders, disabled text, and decoration. Readable roles take the
nearest step that reaches 4.5:1 on `bg-base`, `bg-chrome`, and `bg-elevated` in each mode, in the
neutral roles and in every scope.

`bg-hover` and `bg-pressed` are states laid over whatever sits beneath.

## Tailwind mapping

`@nyte-ai/ui/tailwind.css` maps Tailwind v4's theme onto the tokens with `@theme inline`, so
utilities such as `bg-background`, `text-muted-foreground`, and `rounded-md` paint with the same
values as the components.

```css
@import "tailwindcss";
@import "@nyte-ai/ui/ui.css";
@import "@nyte-ai/ui/tailwind.css";
```
