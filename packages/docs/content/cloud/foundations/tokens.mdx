Components paint with `--nyte-*` custom properties only. The compiled stylesheet declares every
token on `:root`, so loading it is enough.

```css
@import "@nyte-ai/ui/ui.css";
```

An app that compiles StyleX itself gets the same declarations from the compiler, and reads the
tokens through typed constants.

```ts
import { t } from "@nyte-ai/ui/vars.stylex";
```

```ts
const styles = stylex.create({
  note: { color: t.textSecondary, borderRadius: t.radiusBase },
});
```

## Light and dark

Every color is one `light-dark()` pair, so a component follows the `color-scheme` in effect rather
than a class. The package sets no `color-scheme`, so set one. A class toggle works by setting the
scheme under it.

```css
:root {
  color-scheme: light;
}

.dark {
  color-scheme: dark;
}
```

A subtree can take the other appearance on its own with `color-scheme` on any ancestor.

## Overriding

Override a token on an ancestor. A step such as `--nyte-text-tertiary` mixes from an anchor such as
`--nyte-ink`, and the mix resolves where the step is declared. An anchor override on `:root` moves
every step built from it. Below the root, override the step you want to change.

```css
:root {
  --nyte-accent-base: #7c3aed;
}

.preview {
  --nyte-bg-page: #101014;
  --nyte-text-primary: #f4f4f5;
}
```

## Surfaces

`bg-page` is the page and every editor on it. `bg-raised` is a card, dialog, or field above the
page. `material-bg` is the translucent popup surface behind menus and popovers.

## Fills

`fill-hover`, `fill-selected`, and `fill-pressed` are states laid over whatever sits beneath.
`fill-quiet` and `fill-strong` are resting fills. `fill-inverse` is the primary button.

## Tailwind mapping

`@nyte-ai/ui/tailwind.css` maps Tailwind v4's theme onto the tokens with `@theme inline`, so
utilities such as `bg-background`, `text-muted-foreground`, and `rounded-md` paint with the same
values as the components.

```css
@import "tailwindcss";
@import "@nyte-ai/ui/ui.css";
@import "@nyte-ai/ui/tailwind.css";
```
