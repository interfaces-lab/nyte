| Layer         | Owns                                             | Mechanism                                                          |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------ |
| Base UI       | Interaction, focus, ARIA, data attributes        | Headless components                                                |
| `@nyte-ai/ui` | Reusable component styling                       | StyleX `stylex.create` reading [tokens](/cloud/foundations/tokens) |
| The app       | Layout, typography, product identity, composites | Token overrides, `className`, `xstyle`, own components             |

## Token overrides

Override on an ancestor. The app root is the right place, and a preview container works too.
An anchor such as `--nyte-accent-base` moves every step mixed from it only when overridden on
`:root`. Below the root, override the step itself. See [Tokens](/cloud/foundations/tokens).

```css
:root {
  --nyte-accent-base: #7c3aed;
}

.my-preview {
  color-scheme: dark;
  --nyte-bg-raised: #1c1c22;
}
```

Override the tokens that carry identity. Resizing one component to fix one layout is a layout
problem, so solve that one with `className`.

## The three props every styled primitive accepts

| Prop        | Type                  | Purpose                                                                                                          |
| ----------- | --------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `className` | `string`              | Consumer layout, including Tailwind utilities. Appended after the StyleX class.                                  |
| `style`     | `React.CSSProperties` | Inline overrides. Spread after StyleX's inline style, so it wins.                                                |
| `xstyle`    | `XStyle`              | A deliberate StyleX override. Passed as the last argument to `stylex.props`, so it wins by StyleX's merge rules. |

`XStyle` accepts one compiled style, an array, or a conditional. `Button` and `Toggle` narrow
`xstyle` to `ButtonLayout`, placement properties only, so the look stays with the variant. `Hint`
renders no element of its own and takes `xstyle` alone, for the popup.

## Data attributes

The primitives below set `data-slot="<part>"`, so you can target a part from CSS without knowing
the StyleX class. Variant-bearing ones also expose their appearance.

| Component        | Attributes                                     |
| ---------------- | ---------------------------------------------- |
| `Avatar`         | `data-slot="avatar"`, `data-size`, `data-tone` |
| `AvatarImage`    | `data-slot="avatar-image"`                     |
| `AvatarFallback` | `data-slot="avatar-fallback"`                  |
| `Input`          | `data-slot="input"`                            |
| `Textarea`       | `data-slot="textarea"`                         |

Base UI adds its own state attributes on top, such as `data-disabled`, `data-popup-open`,
`data-highlighted`, and `data-checked`. Each component page lists them.

## Dark mode

Tokens use `light-dark()`, so a component follows whichever `color-scheme` is in effect. The
components read no `.dark` class. An app that toggles a class sets `color-scheme: dark` under it.
