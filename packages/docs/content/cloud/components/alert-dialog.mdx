```ts title="Import"
import { AlertDialog, ConfirmDialog } from "@nyte-ai/ui";
```

The same names are exported from their own subpath. Pick one path per file.

```ts title="Subpath"
import { AlertDialog, ConfirmDialog } from "@nyte-ai/ui/alert-dialog";
```

The [Dialog](/cloud/components/dialog) panel with alert semantics. The two look identical, the
behavior differs. Reach for it when the user has to answer before anything else happens.
`ConfirmDialog` is the whole thing assembled for a destructive yes-or-no question.

## Usage

- Use it for a decision the user cannot back out of by clicking away. Delete, discard, overwrite,
  revoke.
- Reach for `ConfirmDialog` first. Build from the `AlertDialog` parts when the question needs other
  content or other actions.
- The footer needs an explicit way out, a Cancel `AlertDialog.Close`. Outside press does nothing.
- Title states the question, description states the consequence.
- The destructive action is the last button and uses `variant="danger"`.
- To open it from a button that is not the trigger, control it with `open` and `onOpenChange` and
  drop the trigger.
- The parts are the [Dialog](/cloud/components/dialog) parts and take the same `xstyle`.

## Anatomy

```tsx
<AlertDialog.Root>
  <AlertDialog.Trigger />
  <AlertDialog.Popup>
    <AlertDialog.Header>
      <AlertDialog.Title />
      <AlertDialog.Description />
    </AlertDialog.Header>
    <AlertDialog.Footer>
      <AlertDialog.Close /> {/* cancel */}
      <AlertDialog.Close /> {/* confirm */}
    </AlertDialog.Footer>
  </AlertDialog.Popup>
</AlertDialog.Root>
```

### Confirm dialog

```tsx
const [open, setOpen] = useState(false);

<Button variant="danger" onClick={() => setOpen(true)}>
  Delete chat
</Button>
<ConfirmDialog
  open={open}
  title="Delete chat?"
  description="The chat and its history are removed."
  onOpenChange={setOpen}
  onConfirm={() => setOpen(false)}
/>
```

While the action runs, pass `pending` to disable both buttons and keep the dialog open, and
`error` to show why it failed.

```tsx
<ConfirmDialog
  open={open}
  pending={signOut.isPending}
  error={signOut.isError ? "Sign-out failed. Try again." : undefined}
  returnFocusRef={signOutRef}
  title="Sign out?"
  description="Other apps using this login are signed out too."
  confirmLabel="Sign out"
  pendingLabel="Signing out…"
  onOpenChange={setOpen}
  onConfirm={() => signOut.mutate(undefined, { onSuccess: () => setOpen(false) })}
/>
```

## Props

### ConfirmDialog

| Prop             | Type                                   | Default       | Description                                                |
| ---------------- | -------------------------------------- | ------------- | ---------------------------------------------------------- |
| `open`           | `boolean`                              |               | Whether the dialog is open.                                |
| `title`          | `string`                               |               | The question.                                              |
| `description`    | `React.ReactNode`                      |               | The consequence.                                           |
| `confirmLabel`   | `string`                               | `"Delete"`    | The danger button's label.                                 |
| `pendingLabel`   | `string`                               | `"Deleting…"` | Replaces `confirmLabel` while `pending`.                   |
| `pending`        | `boolean`                              | `false`       | Disables both buttons and ignores requests to close.       |
| `error`          | `string`                               |               | Shown under the description as an alert.                   |
| `returnFocusRef` | `React.RefObject<HTMLElement \| null>` |               | Where focus lands on close.                                |
| `onOpenChange`   | `(open: boolean) => void`              |               | Called with `false` on Cancel or Escape, unless `pending`. |
| `onConfirm`      | `() => void`                           |               | Called by the danger button. Close the dialog yourself.    |

Focus starts on Cancel.

### Parts

| Part                      | Renders                        | Styling                 |
| ------------------------- | ------------------------------ | ----------------------- |
| `AlertDialog.Root`        | Nothing                        | None                    |
| `AlertDialog.Trigger`     | `<button>`                     | None                    |
| `AlertDialog.Popup`       | A portal, the scrim, a `<div>` | As `Dialog.Popup`       |
| `AlertDialog.Header`      | `<div>`                        | As `Dialog.Header`      |
| `AlertDialog.Title`       | `<h2>`                         | As `Dialog.Title`       |
| `AlertDialog.Description` | `<p>`                          | As `Dialog.Description` |
| `AlertDialog.Footer`      | `<div>`                        | As `Dialog.Footer`      |
| `AlertDialog.Close`       | `<button>`                     | None                    |

Every part except `AlertDialog.Root` accepts `xstyle`, merged last, with `className` and `style`.

## Accessibility

- The popup has `role="alertdialog"`, labelled by `AlertDialog.Title` and described by
  `AlertDialog.Description`.
- Outside press does not close. Escape does. To block that, call `details.cancel()` in
  `onOpenChange` when `details.reason` is `escape-key`.
- Focus moves into the popup on open and returns to the trigger on close. Tab cycles inside the
  popup.
- Content outside the dialog is inert while it is open, and background scroll is locked.
- `ConfirmDialog` sets `aria-busy` on the popup while `pending`, and its error has `role="alert"`.
