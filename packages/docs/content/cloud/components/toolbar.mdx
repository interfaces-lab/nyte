```ts title="Import"
import { Toolbar } from "@nyte-ai/ui/toolbar";
```

## Usage

- `Toolbar.Button` renders a `Button`. Pass a `Button`, `Toggle`, or popup trigger to `render`.
- A disabled item stays focusable when it has `disabledReason`, or with `render` unless you pass
  `focusableWhenDisabled={false}`.

## Anatomy

```tsx
<Toolbar.Root>
  <Toolbar.Button />
  <Toolbar.Separator />
  <Toolbar.Group>
    <Toolbar.Button />
    <Toolbar.Button />
  </Toolbar.Group>
</Toolbar.Root>
```

```tsx
<Toolbar.Root aria-label="Layout">

  <Toolbar.Button render={<Button iconOnly icon="trash" aria-label="Delete" />} />

```

### With a tooltip

```tsx
import { Tooltip, TooltipContent, TooltipTrigger } from "@nyte-ai/ui/tooltip";

<Toolbar.Root aria-label="Changes">
  <Tooltip>
    <TooltipTrigger
      render={
        <Toolbar.Button
          render={<Button iconOnly icon="refresh" aria-label="Refresh" title={undefined} />}
        />
      }
    />
    <TooltipContent>Refresh</TooltipContent>
  </Tooltip>
</Toolbar.Root>;
```

## Props

`Toolbar.Root`, `Toolbar.Group`, and `Toolbar.Separator` take `xstyle`, and `className` and `style`
as plain values. `Toolbar.Button` passes `className` and `style` to what it renders.

## Accessibility

- `Toolbar.Root` renders `role="toolbar"`. Label it with `aria-label` or `aria-labelledby`.
- Arrow keys move focus between items. Focus wraps at the end unless you pass `loopFocus={false}`.
- Orientation follows `orientation` and lands on `data-orientation` for every part.
- A disabled item gets `data-disabled`, plus `data-focusable` while arrow keys still reach it.
