Ramps hold twenty steps per hue. Themes map hues onto scopes. Roles name colour uses through
`light-dark()` pairs and shared ramp values.

```ts
import { role } from "@nyte-ai/ui/styles/vars.stylex";
import { intent, surfaceTheme } from "@nyte-ai/ui/surface-theme";
```

Content, fills, and strokes form stairs, strongest first. Floors are minimum contrasts on base,
muted, elevated, and chrome surfaces, including `fillTertiary` over each, in both schemes and
contrast settings. They cover neutral and category scopes, not intent overrides.
Each content step keeps at least 1.1 times the next step's contrast. Fill and stroke steps also
stay ordered.

## Rules

1. Hover goes up one stair. Pressed and open go up two. Text moves from `contentSecondary` to
   `contentPrimary`. A fill moves from none to `fillTertiary`, `fillSecondary`, then
   `fillPrimary`. A stroke moves from `strokeQuaternary` to `strokeTertiary`, then
   `strokeSecondary`.
2. Never de-emphasise text with `opacity` or `color-mix()`. Pick a lower text stair, never
   `contentQuaternary`. Use opacity for whole-element fades and images.
3. `contentDisabled` is for disabled controls only. A failed, cancelled, or idle item that still
   informs takes `contentTertiary`, or `contentAccent` for an error. A decorative idle dot takes
   `contentQuaternary`.
4. An icon takes its label's stair. Only decoration drops to `contentQuaternary`, such as a
   chevron, a separator, or an idle mark.

- Components read a role. They never write a hex, `rgb()`, `oklch()`, or `light-dark()`.
- Meaning picks a hue through an intent. A category picks one through a scope. Both reuse the
  same role names.

## Content

Text and icons.

| Role                         | Job                                       | Floor                      |
| ---------------------------- | ----------------------------------------- | -------------------------- |
| `contentPrimary`             | Body, titles, values, hovered labels      | 7:1                        |
| `contentSecondary`           | Labels, navigation, pickers, idle buttons | 6:1                        |
| `contentTertiary`            | Metadata, hints, placeholders             | 4.5:1                      |
| `contentQuaternary`          | Decoration only, never text               | 3:1                        |
| `contentDisabled`            | Disabled controls                         | None                       |
| `contentAccent`              | Scoped ink                                | 4.5:1 on a surface         |
| `contentOnInteractiveStrong` | Label on `buttonFill`                     | 4.5:1 on `buttonFill`      |
| `contentOnControl`           | Selected check, knob, thumb               | 3:1 on `bgControlSelected` |

`contentAccent` colours status dots and category ink. Under `intent.danger` it is the error colour.

## Fill

Fills are translucent, so each one works on any surface.

| Role            | Job                                                                   |
| --------------- | --------------------------------------------------------------------- |
| `fillPrimary`   | Pressed filled chip, strong active state, text selection              |
| `fillSecondary` | Pressed ghost, filled-chip hover, selected/open/expanded/current item |
| `fillTertiary`  | Ghost hover, resting chip or secondary control                        |

`layerHover` and `layerPressed` paint `fillTertiary` and `fillSecondary` as a `background-image`,
so they stack over an element's own background.

## Stroke

Borders, dividers, and rings. `strokePrimary` and `strokeAccent` are opaque. The other strokes are
translucent.

| Role               | Job                                         | Floor |
| ------------------ | ------------------------------------------- | ----- |
| `strokePrimary`    | Unchecked checkbox or slider-thumb boundary | 3:1   |
| `strokeSecondary`  | Strong, hover, focus, active border         | None  |
| `strokeTertiary`   | Default border                              | None  |
| `strokeQuaternary` | Subtle divider or edge                      | None  |
| `strokeAccent`     | Scoped stroke                               | None  |

## Hue scopes

Pass a scope to `props()` to apply its ramp and tinted roles. Neutral control boundaries, unchecked
controls, and `contentOnControl` stay neutral. `custom` reads `--nyte-custom-hue` (default `250`)
and `--nyte-custom-chroma-scale` (default `1`).

<HueScopes />

```tsx
import { create, props } from "@stylexjs/stylex";
import { surfaceTheme } from "@nyte-ai/ui/surface-theme";
import { role } from "@nyte-ai/ui/styles/vars.stylex";
import { text } from "@nyte-ai/ui/styles/text.stylex";

const styles = create({
  badge: { color: role.contentSecondary, backgroundColor: role.fillTertiary },
});

export function Added() {
  return <span {...props(surfaceTheme.green, text.sm, styles.badge)}>Added</span>;
}
```

## Ramps

Each hue runs from `0`, lightest, to `150`, darkest. Scheme-dependent roles pick light and dark
ramp values. Translucent ramps supply fills and strokes per scheme.
`custom` builds its ramp from `--nyte-custom-hue`, with no fixed values.

## Intents

<IntentTable />

`intent.primary` sets `buttonFill` to blue step `80` without category lightness clamping.
`intent.danger` maps `contentSecondary` to `contentAccent`, with a 4.5:1 floor rather than 6:1.

The focus ring ignores scopes. It reads `appearance.focusRing`, blue by default and `Highlight`
in forced colors. The host can make the ring transparent for pointer focus.

## High contrast

Under `prefers-contrast: more`, content steps move toward the ramp's end, preserving order.
Fills, translucent strokes, and control hover/press states strengthen.
`strokePrimary`, `strokeAccent`, and surfaces keep their steps.
