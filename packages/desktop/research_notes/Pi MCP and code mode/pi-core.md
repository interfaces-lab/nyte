# Pi core MCP, codemode, tools, and child agents

## Which repository and revision did this research inspect, and are MCP and codemode actually first-party?

### Takeaway
Yes. The requested `earendil-works/pi` repository has a standalone MCP client, a standalone QuickJS codemode runtime, and coding-agent integrations shipped as built-in, replaceable extensions. This is not an extension-ecosystem-only implementation.

## What does Pi's MCP implementation do, and which MCP features are absent?

### Takeaway
Pi owns JSON-RPC request handling, initialization, tool listing/calling, resources, stdio and Streamable HTTP transports, OAuth, reconnection, and tool-list updates. The coding-agent integration does not implement an MCP sampling or elicitation bridge to its model or user UI.

### Cited Findings
- The client installs only server-request handlers for `ping` and, when roots are supplied, `roots/list`. Initialization sends configured capabilities and adds roots capability when applicable, validates the negotiated protocol version, then emits `notifications/initialized`. Supported versions are `2025-11-25`, `2025-06-18`, `2025-03-26`, and `2024-11-05`. [Handlers and handshake](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/client.ts#L171-L179); [initialization](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/client.ts#L213-L243); [version constants](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/protocol/types.ts#L4-L10).
- The actual coding-agent connection constructs `McpClient` with name, version, timeout, and the workspace root. It does not supply sampling or elicitation capabilities and does not install corresponding request handlers. It subscribes to tool/resource list-change notifications and lists tools only when the server advertises tools capability. [Connection setup](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L371-L409).
- The standalone type permits `sampling` and `elicitation` capability fields, and the generic client exposes `setRequestHandler`. Those are extension points, not implemented Pi sampling/elicitation behavior. Unknown server requests receive JSON-RPC method-not-found. [Capability type](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/protocol/types.ts#L23-L35); [generic hook](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/client.ts#L262-L267); [unknown-request response](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/client.ts#L487-L499).
- Source search for `elicitation`, `sampling/createMessage`, `prompts/list`, and `prompts/get` in `packages/mcp/src` and `packages/coding-agent/src` found the capability type but no dedicated handlers/helpers for these methods. The standalone README explicitly excludes batch JSON-RPC, legacy HTTP+SSE, MCP servers, sampling, and tasks from its initial core. The integration's connection path above provides affirmative evidence of which handlers it actually wires. [Declared omissions](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/README.md#L116-L132); [wired integration](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L371-L409).
- MCP Apps are not rendered. The resource adapter omits `ui://` and MCP-app HTML resources, while exposing ordinary resource listing, templates, and reads. [Resource behavior](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/mcp.md#L212-L224).
- `createDefaultTransport` selects Streamable HTTP for URL entries and stdio otherwise. Stdio receives resolved command, arguments, working directory, environment, and piped stderr. [Transport factory](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L97-L121).
- User `mcp.json` loads first; trusted project `.pi/mcp.json` can override it. Project config is not read without project trust. [Config loader](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/config.ts#L115-L123); [documented precedence](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/mcp.md#L30-L34).
- OAuth implementation is first-party source adapted from official MCP TypeScript SDK v1.29.0, with its license bundled. The standalone package does not choose token storage or open the browser. Pi's coding-agent layer supplies those policies. [OAuth documentation and attribution](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/README.md#L58-L114).
- Connections share an opening promise, reconnect on demand, and track `connecting`, `connected`, `disconnected`, `needs-auth`, `failed`, and `closed`. Initial HTTP connection retries use 250 ms and 1,000 ms delays. Generic transient tool-call failures are not retried because the call may have run. Read-only requests can retry, and a session-expired response has a separate reconnect-and-retry path. [State and delays](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L47-L56); [shared connection](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L249-L259); [retry distinctions](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L286-L311).
- Tool names become provider-safe `mcp__<server>__<tool>`, bounded to 64 characters. Sanitization collisions and long names receive stable SHA-256-derived suffixes. Registration hashes all colliding tool names rather than letting list order decide which keeps the plain name. [Naming function](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/tools.ts#L76-L91); [collision assignment](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L353-L395).
- When the server withdraws tools, the extension re-registers their definitions as `hidden`, since the coding-agent tool API has no unregister operation. Disabled servers are similarly hidden. [Withdrawal handling](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L397-L413).
- Direct/model-facing MCP text over 20 KiB is middle-truncated and saved to a temporary file with mode `0600`. Scripts instead receive the complete `CallToolResult` minus `_meta`, including structured content and `isError`. Direct calls mark `isError`; structured script results can resolve with that flag so the script can inspect them. [Limit and private file](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/tools.ts#L43-L69); [truncation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/tools.ts#L118-L143); [result conversion](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/tools.ts#L207-L227).

### Inferences
- For absent sampling/elicitation or a custom MCP method, the provided mechanism is a host-installed request handler, not an automatic call into Pi's agent/UI. No source-backed recommendation to turn these requests into child user prompts was found. [Generic handler API](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/mcp/src/client.ts#L262-L267).
- For ordinary integration, the documented alternatives are first-party extension factories in SDK sessions or standalone `McpClient` wrapped as `AgentTool`s, not a mandatory third-party adapter. [SDK example](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/sdk/14-codemode-mcp.ts#L13-L50); [agent adapter](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/agent/examples/mcp-codemode/tools.ts#L35-L76).

### Gaps
- No claim that the generic JSON-RPC client makes custom methods impossible. It can issue generic requests and install generic handlers. Absence here means no built-in dedicated integration at this SHA.
- No full protocol conformance certification or live external-server test was performed. The README's supported-feature list is narrower than all generic methods a host might implement.

## How are direct tools registered, filtered, and executed?

### Takeaway
Pi separates all registered tools, model-active tools, and nested-callable tools. Exposure is a presentation/reachability policy; an allowlist or denylist filters the registry itself, including dynamically registered tools.

### Cited Findings
- `ToolDefinition` includes a TypeBox input schema, optional output schema and structured content, exposure, namespace, annotations, execution mode, `defaultActive`, `prepareLoadout`, and execute/render methods. [Definition contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/types.ts#L563-L644).
- `pi.registerTool` validates that parameters are an object, stores by name in the extension's map, and calls runtime refresh. It can be used during extension load or later. Re-registering a name in that extension replaces its current definition. [Implementation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/loader.ts#L288-L300); [load-time refresh default](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/loader.ts#L168-L180).
- Generic exposures: `direct` is declared while active and nested-callable while active; `model-only` is declared while active but never nested-callable; `codemode` is nested-callable whenever registered and normally listed in codemode; `deferred` is likewise callable but omitted from codemode listings; `hidden` is unreachable. `direct` and `model-only` activate on registration unless `defaultActive: false`. [Contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/types.ts#L494-L509); [default activation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/types.ts#L603-L615).
- `_getCallableTools` implements exactly that rule. `_applyToolLoadout` ignores unknown/hidden names; active orchestration tools may replace descriptions and suppress request declarations without removing the corresponding tools from the active or callable sets. [Implementation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L1497-L1571).
- `_isAllowedTool` requires allowlist membership when an allowlist exists and rejects denylisted names. Both definitions and wrapped executors are filtered before constructing the registry. Thus activation cannot reintroduce tools removed by the session tool filter. [Predicate](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L1503-L1509); [registry filtering](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L3457-L3517).
- SDK `tools` is an allowlist, not merely the initial active selection; `excludeTools` applies after it. For adding an orchestrator without excluding MCP tools, the SDK example uses `defaultTools` overrides, explicitly warning that `tools` would hide unnamed MCP tools. [SDK contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/sdk.ts#L60-L78); [example warning](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/sdk/14-codemode-mcp.ts#L4-L10).
- `runToolCall` resolves from the supplied tool list, prepares arguments, validates them, runs `beforeToolCall`, executes, and runs `afterToolCall`. Missing tools, invalid inputs, blocked calls, and exceptions become error outcomes. [Lookup/validation/blocking](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/agent/src/agent-loop.ts#L707-L752); [reusable pipeline](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/agent/src/agent-loop.ts#L789-L817).
- Codemode nested calls use the same pipeline with the session's callable registry and before/after hooks. They do not call an MCP client's executor directly outside the hook pipeline. [Session wiring](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L700-L735).
- `NestedToolCallRunner` assigns `<callerId>/<n>` IDs, emits events with `parentToolCallId`, records usage/errors, and serializes sequential tools. A scope already holding the sequential queue lets its own descendants run without deadlocking behind itself. [Runner and sequencing](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/nested-tool-calls.ts#L160-L236).
- Recorder bounds are 256 calls, 8 KiB arguments per call, 32 KiB arguments total, and 500 error characters. These bound recording, not tool-call permission or the total number of actions executed. [Limits and recording](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/nested-tool-calls.ts#L21-L99).

### Inferences
- For Nyte, copy the separation between registry filtering and declaration activation. Making a tool inactive is insufficient to remove a `codemode`/`deferred` capability; removing it from the child registry is the relevant operation. [Callable predicate](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L1503-L1519).
- `model-only` means "not callable by other tools," not "interactive root-only." It does not remove a tool from child sessions by itself. Child registry policy still needs an allowlist/denylist. [Exposure contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/types.ts#L494-L509); [filter predicate](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L1503-L1505).

### Gaps
- Tool filters are not an OS sandbox and do not stop trusted extension initialization code from running. Pi explicitly documents that extensions and subprocesses use the local user's privileges. [Security boundary](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/security.md#L1-L7).

## What is lazy discovery/activation, and what does it actually defer?

### Takeaway
Pi discovers server tool metadata during background connection, then avoids eagerly declaring that metadata to the model. `tool_search` activates matches for the next model call; codemode search discovers callable tools without changing model declarations. These are different mechanisms.

### Cited Findings
- MCP config exposures are `codemode`, `deferred`, `direct`, and `hidden`; default is `codemode`. Per-tool exact names override patterns, and the first matching `*` pattern wins. `codemode-deferred` is an alias for `codemode`. [Config contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/mcp-servers.ts#L8-L42); [resolution](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/mcp-servers.ts#L191-L198).
- Important distinction: MCP exposure `codemode` maps to generic tool exposure `deferred`, so MCP tools are not embedded in the codemode description. MCP `codemode` and MCP `deferred` therefore produce equally callable/discoverable tools; their difference is whether the integration automatically enables `codemode` or `tool_search`. [Mapping](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/tools.ts#L35-L41); [automatic activation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L451-L484).
- Codemode and tool search register inactive. MCP activates discovery from configured exposures before connections finish, only if the registered tool is Pi's actual implementation as identified by its schema, not merely a name match. `autoEnableCodemode: false` disables automatic codemode activation; the integration warns once if neither discovery route is active. [Activation implementation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L451-L484); [inactive tool search](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/index.ts#L1-L18); [inactive codemode](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/index.ts#L31-L44).
- On session start every enabled MCP server connects in the background. The client code loads only when servers are configured. The first prompt waits once, at most 10 seconds by default, for direct servers. It does not wait for ordinary codemode/deferred servers. [Startup and bounded wait](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L954-L1014).
- Before a codemode/tool-search/resource call, the integration waits for relevant pending servers. A script mentioning a server namespace waits for that server. `searchTools`, `describeTool`, `describeNamespace`, or `ALL_TOOLS` anywhere in the source causes all pending servers to be awaited. `tool_search` and resource tools wait for all pending servers. This is lexical source detection, not a JavaScript AST or demand-driven network connection system. [Source heuristic](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L216-L223); [wait hook](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L1026-L1045).
- A bounded `mcp_servers` system-prompt section lists indirect servers, their access route, and short summaries; longer instructions are available from `describeNamespace`. The section updates before a prompt, rather than expanding individual tool descriptions as servers connect. [Renderer](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L149-L214); [update hook](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L1016-L1024).
- Tool search documents contain tool names, descriptions, recursive schema property names/descriptions, and namespace description/instructions. Tokenization splits camelCase and punctuation, lowercases, removes stop words, and uses simple plural stemming. BM25 defaults are `k1=1.2`, `b=0.75`; positive-score ties preserve document order. [Search document](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/tool.ts#L63-L116); [ranker](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/tool.ts#L118-L157).
- `tool_search` searches only inactive generic `codemode`/`deferred` tools. It defaults to eight matches, validates nonempty query and positive integer limit, and calls `setActiveTools([...active, ...matches])`. The response gives names/short descriptions; schemas become declarations for the next model request through normal tool activation. It is `model-only`, so scripts cannot call this declaration-changing operation. [Activation implementation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/tool.ts#L191-L246); [default limit](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/tool.ts#L20-L21).
- Codemode `searchTools` ranks only that execution's callable tools and returns identifier plus declaration-bearing description. It can filter namespace; `describeTool` accepts raw or sanitized names; `describeNamespace` returns summary, instructions, and tool names. None of these functions calls `setActiveTools`. [Discovery globals](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L451-L517).
- Codemode listings use a 3,000-estimated-token default inline budget, exclude generic deferred tools, and remain unchanged when tool search activates them. Mode `on` retains direct declarations and annotates how scripts call them. Mode `only` suppresses active direct declarations from model requests but retains callable tools. [Loadout policy](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/tool.ts#L319-L363); [budget constant](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/tool.ts#L153-L154).
- Search activation persists as normal tool declarations in the transcript. Restoring a branch tracks allowed pending tool names until their definitions arrive; starting the next run discards still-unregistered pending names. Tests check navigation, resume, and reload behavior. [Restore/start logic](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L1757-L1783); [branch test](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/test/suite/agent-session-mcp.test.ts#L822-L864); [resume/reload cases](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/test/suite/agent-session-mcp.test.ts#L1053-L1119).

### Inferences
- Pi defers schema exposure to the model, not server startup or initial metadata collection. A Nyte implementation that only adds lazy imports is not equivalent to Pi's lazy tool discovery. [Background connection](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L954-L991); [declaration activation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/tool.ts#L200-L213).
- Preserve the difference between search-and-activate and search-within-code. The former changes subsequent provider requests; the latter can immediately call a discovered function within the same script. [Activation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/tool-search/tool.ts#L200-L213); [same-script discovery/call test](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/test/suite/agent-session-mcp.test.ts#L780-L819).

## How does codemode execute code and preserve ordinary tool policy?

### Takeaway
Each execution gets a fresh QuickJS WebAssembly VM in a Node worker. The VM can only reach host capabilities that the host injects, and Pi wraps ordinary tool capabilities through its normal validated, hook-aware tool pipeline.

### Cited Findings
- A worker creates QuickJS with the supplied wasm, memory limit, stack limit, and shared interruption flag. Code runs as an async function body, with top-level await/return. The worker relays serialized calls and output; it never passes Node objects into the VM. [Worker setup/bridge](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/worker.ts#L52-L100); [code execution](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/worker.ts#L142-L154).
- The prelude keeps the host bridge in a closure, creates null-prototype tool tables, exposes both identifier aliases and raw names, and freezes tool lists/objects. [Prelude contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/prelude-source.ts#L1-L27); [tool construction](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/prelude-source.ts#L102-L114).
- The host snapshots registered tools at execution start, resolves incoming tool names against that map, parses arguments as JSON, and invokes the injected executor with an abort signal. Script errors and tool errors are returned through structured result messages. The standalone sandbox does not validate arguments against advertised JSON schemas; the integrating host must do so. [Snapshot](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/host.ts#L334-L353); [call boundary](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/host.ts#L210-L240); [schema caveat](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/README.md#L99-L113).
- Finishing, aborting, or timing out aborts pending host-call controllers, sets the shared interrupt flag, and terminates the worker. Injected tools must honor their signal for host-side work to actually stop. [Finish](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/host.ts#L242-L272).
- No timers, fetch, process, require, modules, or WebAssembly exist in the script. `eval` and `Function` only create more code in the same VM. Tests assert unavailable host globals and inability to import `node:fs`. [Runtime contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/README.md#L38-L51); [actual tests](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/test/sandbox.test.ts#L631-L677).
- Coding-agent execution snapshots `ctx.tools`, creates adapters calling `ctx.executeTool`, injects discovery globals, sets a 256 MiB VM memory limit, and closes the sandbox in `finally`. `codemode` itself is `model-only`, preventing script recursion through its callable list. [Integration](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L342-L397); [memory constant](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L57-L57); [model-only tool](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/tool.ts#L365-L383).
- The standalone sandbox defaults to a 300,000 ms deadline, but the coding-agent integration explicitly supplies Infinity unless the source `timeout_ms` option is present. Do not assume a default five-minute limit for Pi's coding-agent tool. [Standalone default](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/host.ts#L22-L22); [integration override](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L377-L389).
- Ordinary tools with output schemas return their structured content to scripts. Otherwise scripts get concatenated text, and error outcomes throw. MCP adapters deliberately provide an output schema wrapping the complete `CallToolResult`, so scripts can inspect `isError` without automatically throwing. [Script conversion](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L308-L314); [MCP result schema](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/tools.ts#L100-L115).
- Only script output and return value become normal model-facing output. Results of internal calls can be reduced inside the script; call metadata stays in nested-call records. Successful store writes persist as `codemode-store` custom entries; failed scripts do not commit writes. [Result/store handling](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L398-L433); [branch-aware store documentation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/codemode.md#L53-L55).
- `// @options:` supports `max_output_tokens` and `timeout_ms`; the source parser replaces the directive with an empty line to preserve source line numbers, rejects unknown/invalid fields, and exports a provider grammar. [Parser](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/source.ts#L56-L114).
- Codemode can also inject model catalog/classifier/image helpers. These are separately provided globals, not ordinary tool calls; the integration limits those calls, accumulates their usage, and documents them independently. This capability is optional via the factory's `models` setting. [Optional setting](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/index.ts#L13-L19); [injection](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/codemode/execute.ts#L377-L384); [documented model calls](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/codemode.md#L90-L92).

### Inferences
- The copyable pattern is VM isolation plus a narrow host capability map plus the existing tool pipeline. Running generated code in Node `eval`, or invoking MCP calls directly from a worker without the session policy path, would omit essential parts of Pi's design. [Worker boundary](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/worker.ts#L52-L100); [validated nested pipeline](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L700-L735).
- This sandbox restricts JavaScript access, not injected tool effects. Injecting `bash` intentionally delegates process execution to the host tool. That is capability delegation, not a sandbox escape. [Host executor boundary](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/src/runtime/host.ts#L220-L225).
- For Nyte's Electron main process, the Node worker and explicit wasm/worker URL design is reusable. Keep it outside the renderer; ship an actual worker entry and QuickJS wasm asset. Pi documents bundled-host configuration explicitly. [Bundled host setup](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/codemode/README.md#L79-L97).

### Gaps
- No sandbox escape audit, host memory stress test, or audit of all injected model helpers was performed. The VM heap limit is not a documented cap on total host-process memory or buffered output.

## How do subagents and child tool scoping work?

### Takeaway
The regular CLI's showcased subagent implementation is an example extension that starts a fresh noninteractive Pi process. It supplies an agent-specific tool allowlist when configured; it does not automatically intersect with the parent's active tools or forward the parent's ephemeral registry. The repository also contains separate experimental durable child-conversation implementations.

### Cited Findings
- `subagent` is not in the CLI's built-in extension list. Its example README instructs the user to install/symlink the extension and agent definitions. Each agent uses a separate process and isolated context. [Built-in list](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/index.ts#L1-L14); [example/install](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/README.md#L1-L53).
- Agent definitions contain frontmatter name, description, optional tools/model, and body prompt. Tools accept a comma-separated string or a string array; empty/invalid parsed lists become undefined, rather than an explicit empty allowlist. [Tool parsing](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/agents.ts#L41-L59); [definition format](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/README.md#L125-L146).
- `runSingleAgent` always starts `--mode json -p --no-session`, inherits the dispatcher's model/thinking only when no agent model is specified, appends `--tools` only for a nonempty agent tool list, writes the delegated prompt to a temporary file, and adds it with `--append-system-prompt`. The child receives `Task: ...`, not the parent's conversation history. [Argument construction](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L272-L341).
- Child spawn uses `shell: false`, configured/default cwd, stdin ignored, stdout/stderr piped. No parent active-tool snapshot, parent denylist, ephemeral MCP server registrations, UI bridge, or explicit project-trust override is passed in this invocation. Child configuration comes from its own CLI startup and applicable filesystem/user configuration. [Spawn and complete preceding arguments](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L300-L350).
- Scope defaults to user-level agents. Project/both scope is opt-in; project agent names override user agent names under both. The parent extension asks for confirmation only for requested project-local agents when it has UI, confirmation is enabled, and the project is not trusted. Trusted projects skip that extra per-call prompt. [Discovery precedence](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/agents.ts#L128-L146); [dispatch/default scope](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L483-L491); [confirmation condition](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L520-L548).
- Child trust is not a passed boolean in this sample. A fresh process resolves command-line override, extension decision, saved trust, and global default policy. Without UI, unknown trust under the default ask policy returns false. Saved trust applies to matching directory/parents. [Trust resolver](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/project-trust.ts#L46-L95); [saved/noninteractive policy](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/security.md#L59-L82).
- Experimental `src/experimental/durable/subagent.ts` creates a task-owned child conversation as a copy of the parent agent and removes the `Subagent` extension, so the child cannot recursively delegate with it. The request ID makes reruns find the same submission. The child conversation survives completion for later user steering. [Actual durable child implementation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/experimental/durable/subagent.ts#L19-L51).
- Experimental vacation research shows stricter scoping: configure the child with exactly `extensions: [Search]`, rather than inheriting the planner/research tools. It creates a background task and later posts a report into the parent's conversation as follow-up input. This is experimental durable code, not the normal subprocess extension. [Child scope/background setup](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/experimental/vacation/vacation.ts#L105-L126); [report delivery](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/experimental/vacation/vacation.ts#L64-L99).

### Inferences
- Do not copy the sample subprocess runner and assume child tools inherit parent restrictions. If Nyte requires a parent-child capability intersection, construct it explicitly and pass/filter the child registry. Pi's core allowlist filtering is the reusable enforcement mechanism; the subprocess sample is not an inherited-capability implementation. [Sample invocation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L300-L350); [registry filtering](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/agent-session.ts#L3457-L3517).
- No child user prompts is intended policy for this research and Nyte, not a bypass. Pi's subprocess example supports that outcome by using JSON/print execution with no stdin or UI forwarding. Root trust inheritance should remain a Nyte host policy; the Pi example's filesystem-based trust re-resolution is not an exact match. [Spawn](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L300-L350); [no-UI trust result](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/project-trust.ts#L86-L95).

### Gaps
- The example is not a general background-agent service with task/send/await/stop APIs. The experimental durable implementation is a different architecture; do not merge its semantics into claims about the regular CLI sample.
- No explicit automatic exclusion of a user-installed question tool exists in the subprocess argument list. No-UI behavior and tool exclusion are distinct. The host must choose the child registry policy. [Complete argument/spawn path](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/subagent/index.ts#L300-L350).

## What happens to user interaction in noninteractive agents, and what is policy versus defect?

### Takeaway
Print/JSON agents have no UI by design. RPC may carry supported user dialogs, so RPC is not synonymous with a background child. Question tools and permission extensions must supply their own noninteractive policy; there is no native MCP elicitation-to-user bridge.

### Cited Findings
- Extensions load in interactive, RPC, JSON, and print modes. Interactive mode has the full terminal UI; RPC forwards supported dialogs but not custom terminal components; JSON and print have no UI. The docs recommend `ctx.mode === "tui"` for terminal-only work and `ctx.hasUI` for general supported dialogs. [Mode contract](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/extensions.md#L240-L249).
- The actual no-op UI resolves select/input/editor to undefined and confirm to false; notifications/status/widgets are no-ops. `hasUI` checks whether the active UI context differs from this no-op context. [No-op implementation](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/runner.ts#L323-L354); [hasUI](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/extensions/runner.ts#L616-L622).
- RPC dialogs emit `extension_ui_request` with a generated ID and wait for a matching response. Cancellation/abort/optional timeout resolves default values. This does not apply to the sample subagent's JSON output stream. [RPC request lifecycle](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L93-L150).
- No built-in ask-question tool appears in the base-tool inventory or the CLI built-in extension list. The repository supplies an example `question` extension; it requires TUI mode and otherwise returns text beginning `Error: UI not available`, with `answer: null`. It does not prompt noninteractive children. This example is registered with default direct exposure, not `model-only`, and its no-UI result does not set `isError`. [Base inventory](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/core/tools/index.ts#L93-L105); [built-in extensions](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/index.ts#L1-L14); [example question behavior](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/question.ts#L44-L73).
- `--exclude-tools ask_question` is an explicit CLI example for suppressing one tool while retaining the rest. This is a named-tool filter, not an automatic UI-capability filter. The actual question sample is named `question`, so exclusion must use the actual installed tool's name. [CLI example](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/cli/args.ts#L388-L392); [sample name](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/question.ts#L44-L50).
- Pi itself does not ask for approval before every tool call. The sample permission-gate extension chooses to block dangerous bash calls when no UI exists; with UI it asks the user. That policy is extension-owned and must not be mistaken for a mandatory built-in policy. [Security statement](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/docs/security.md#L1-L7); [sample no-UI blocking](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/examples/extensions/permission-gate.ts#L10-L32).
- MCP sign-in is explicit user/CLI action. In-session login checks `ctx.hasUI`; without it the command reports interactive mode is required. A server that needs authentication produces a needs-sign-in failure instead of initiating a tool-driven user dialog. [Session login check](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/index.ts#L923-L949); [request failure policy](https://github.com/earendil-works/pi/blob/86dfceec402ad77e563bf4feab5f26c42d5f5db6/packages/coding-agent/src/extensions/mcp/runtime.ts#L307-L311).
