Subagent UI: redesign

Built from three references: the Cursor IDE bundle, the Cursor CLI bundle (~/.local/share/cursor-agent), and Nyte's old UI on main. All three draw a subagent the same way: one compact row per child, and that row is the result. None of them puts the child's answer in the transcript. That answer is for the parent model.

What the references do

Cursor IDE (SubagentTaskCard)

  • One row per Task: 20px indicator (a 3×3 dot spinner while running, otherwise a 6px dot), the title, a dim model label, then one status line.
  • The status line is the child's current step ("Reading foo.ts", "Thinking", the first 50 characters of its reply) with a shimmer. Each text stays at least 1.2s.
  • Finished rows show "Completed", "Stopped" or "Stopped with error", with an unread dot. The result isn't shown inline.
  • Click or Enter opens the child's chat; Alt or Cmd opens it beside the current one. The child's own children appear as nested rows.
  • 14px/22px, regular weight, sans. No token count or elapsed time.

Cursor CLI (the screenshots)

  • Task calls from one step are grouped under "Running N agents… (k done)". When all finish: "N agents completed" or "N completed, X cancelled".
  • Each agent shows a title (up to 40 characters) and a status: the child's last tool call ("Finding apps/**/package.json"), "✓ Done" or "✗ Cancelled".
  • The tasks panel ("Tasks (1 task)") shows each task's prompt and elapsed time. Enter replaces the chat with the child's transcript; Esc goes back.
  • When a background task finishes, the transcript gets one line: "Finished <title>".

Nyte main (old TUI and desktop)

  • The create card is the child: its glyph follows the child's run, there's one fixed-height activity row, and the model is shown in dim text.
  • The child's id was known as soon as the call started (childOf(head, run, call)), so the card could be clicked immediately.
  • No report row. "A background result answers the model, not the user." The card turning ✓ is the result.
  • await is never drawn; the child's card already shows that state. send, read and stop are one line each.
  • Depth lives in the inspector or tray: elapsed time, model, the full transcript, and next/previous task.

Rules taken from them

  1. The child's row is the result. It shows the indicator, title, model, and one line: the current step, or how it ended.
  2. The child's answer never goes in the transcript. To read it, open the child (TUI inspector, desktop tray).
  3. Parallel children share one block: "Running 5 agents… (1 done)", then "5 agents completed".
  4. A background finish is one line, not a message. Core wakes the parent with the report: a running parent takes it at its next step, and an idle parent whose last run completed starts a new run. The line names why the parent started talking again. The only case to call out is "held": the parent stopped or failed, so the report waits for your next message.
  5. Don't draw what the card already shows. await disappears; send, read and stop stay as one line each.

Each agent is the old daniel/schema card, unchanged: ● title model · thinking, then one dim activity row, one line high and cut off if too long. That row is the child's newest step: a tool call, the first line of its last text, or its failure. The header line is the one thing taken from the Cursor CLI. Enter or a click on any agent row opens the inspector. That's the existing /tasks inspector with the child's full transcript, elapsed time and model. The tasks line ("● 2 running in background · ↓ view") stays as it is.
