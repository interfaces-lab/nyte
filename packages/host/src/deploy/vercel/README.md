# Vercel

This directory is a Nitro app template for running a Nyte host on Vercel; the deployer builds it with `nitro build --preset vercel` (§42m). `nitro.config.ts` serves `server/`, compiles the workflow in `server/workflows` through the `workflow/nitro` integration, lets functions run up to 300 s, and schedules the repair cron. `server/routes/[...].ts` sends every path to the listener of a host composed once per function instance (`server/utils/host.ts`): sessions in Postgres (`DATABASE_URL`), tools in the Vercel Sandbox named by `NYTE_SANDBOX` (`server/utils/sandbox.ts`, over `@vercel/sandbox`), and the store re-read every second so each instance sees the others' writes. A request instance admits and dispatches each head an admission makes owed a step to `driveHead` in `server/workflows/drive.ts` (the `dispatch` execution kind), which advances it one step at a time, each step covering its session, and sleeps durably between steps until nothing is owed. The cron calls `GET /.nyte/repair` every minute (`NYTE_REPAIR_SCHEDULE` overrides; Hobby plans allow daily only) to restart a drive for any head a failed dispatch left behind; that route answers only `Authorization: Bearer <CRON_SECRET>`, which Vercel sends when `CRON_SECRET` is set, and answers `unknown` without it. Install `nitro`, `h3`, `workflow` and `@vercel/sandbox` (optional peers of `@nyte-ai/host`), and set `NYTE_TOKEN` (at least 16 characters), `CRON_SECRET`, and, to enable `secrets.set`, `NYTE_SECRET_KEY` (base64).
