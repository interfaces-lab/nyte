# Vercel

This directory is a Nitro app template for running a Nyte host on Vercel; the deployer builds it with `nitro build --preset vercel` (§42m). `nitro.config.ts` serves `server/`, compiles the workflow in `server/workflows` through the `workflow/nitro` integration, lets functions run up to 300 s, and schedules the repair cron. `server/routes/[...].ts` sends every path to the listener of a host composed once per function instance (`server/utils/host.ts`): sessions in Postgres (`DATABASE_URL`), tools in the Vercel Sandbox named by `NYTE_SANDBOX` (`server/utils/sandbox.ts`, over `@vercel/sandbox`), and the store re-read every second so each instance sees the others' writes. The host's execution is `dispatch`: after each commit it hands every head a wake makes owed a step to `driveHead` in `server/workflows/drive.ts`, which advances it one step at a time, each step covering its session, sleeps durably between steps until nothing is owed, and ends when another instance holds the head. The cron calls `GET /.nyte/repair` every minute (`NYTE_REPAIR_SCHEDULE` overrides; Hobby plans allow daily only) to dispatch again any head a failed dispatch left owed; that route answers only `Authorization: Bearer <CRON_SECRET>` (compared in constant time; Vercel sends it when `CRON_SECRET` is set), anything else `unauthenticated`, and `unknown` when `CRON_SECRET` is unset (`server/utils/repair.ts`). Jobs run per instance: a client reads another instance's job only through its exit report. Install `nitro`, `h3`, `workflow` and `@vercel/sandbox` (optional peers of `@nyte-ai/host`), and set `NYTE_TOKEN` (at least 16 characters), `CRON_SECRET`, and, to enable `secrets.set`, `NYTE_SECRET_KEY` (base64).
