Diffs, keystrokes and subagents: Nyte TUI vs OpenCode

Compares OpenCode's dev branch (packages/tui) with ours. Your screenshots showed three of our bugs, and all three are fixed.

1 · "Error parsing diff" on a new file fixed

Core numbers an empty side the way unified headers do: oldStart: 0. jsdiff's StructuredPatch stores it one higher and subtracts 1 when it formats. We passed core's number straight through, so the header came out as -1.

core write → hunk { oldStart: 0, oldLines: 0, newStart: 1, newLines: 161 }
patchDiff → formatPatch()  @@ --1,0 +1,161 @@   ← OpenTUI parse fails
fixed     → oldStart + 1    @@ -0,0 +1,161 @@    (same for a file emptied: newStart)

Why the colors looked wrong

When OpenTUI can't parse a diff, it falls back: it prints a hardcoded #ef4444 error line, then highlights the raw patch with tree-sitter's diff grammar. That grammar's diff.plus/diff.minus colors are our changed-word emphasis tokens, so every row got word-emphasis color and no gutter. Our diff tokens never applied because the diff never rendered.

before: fallback

✓ edited show-me-subagent-reports.html +161 -0
Error parsing diff: Hunk at line 1 contained invalid line
@@ --1,0 +1,161 @@
+<!doctype html>
+<html lang="en">
+<head>

after: our diff tokens

✓ edited show-me-subagent-reports.html +161 -0
1 +<!doctype html>
2 +<html lang="en">
3 +<head>
4 +<meta charset="utf-8">

OpenCode never hits this. Its Write tool skips diffs and shows the content as <code> with line numbers, while Edit and Patch use a unified patch string built by the server.

2 · Every keystroke rebuilt every diff fixed

Each keystroke produces a new ScreenModel. Values read through screen() are plain getters, so any memo that touched one subscribed to the whole screen. That made the card build a new diff object, which made <For> destroy the <diff> and mount a new one: parse and tree-sitter highlighting all over again, for every diff in view.

keystroke → reduce → deriveScreen → new ScreenModel
  MessageView   expanded = () => scope.model().toolOutput === "expanded"   getter: tracks screen()
  ToolCard      createMemo(() => toolCard(msg, scope.tasks(), props.expanded))  reruns
  CardView      body().diff  → new OutputDiff object
  DiffView      <For each={diff.files}>  → new items → destroy + mount <diff>, re-highlight

fixed
  MessageView   expanded = createMemo(…)          a boolean: unchanged → nothing downstream runs
  Transcript    tasks = createMemo(() => props.tasks())  fires only when the task list changes
  ToolCard      reads tasks only for delegate cards   a running subagent no longer rebuilds edit diffs

I checked this with a throwaway render test (since deleted): mount a transcript containing a diff, change the draft three times, then compare the DiffRenderable. Old code: destroyed after the first keystroke. With the fix: the same instance after all three.

How OpenCode avoids it

MechanismOpenCodeNyte TUI
Prompt textLives in the native textarea and a prompt-local store. The transcript never reads it (component/prompt/index.tsx:358)Lives in State.local.draft, so it flows through the single deriveScreen memo. Anything reading screen() unmemoized re-runs
RowsA keyed createStore updated with reconcile(…, { key }) (routes/session/rows.ts:86)keepEqual and the per-key Row cache. Same goal
PartsRows carry IDs, and each part is resolved by createMemo. splitPatchHunks is memoized (patch-diff.tsx:39)Same ID-plus-memo shape. The leak was the props read alongside the message

The lasting lesson: inside the transcript, read anything derived from screen() through a createMemo that returns a stable value, never a bare getter.

Instant reports done

As in OpenCode, what you see is now separate from what the model receives. A finished subagent's report draws in the transcript immediately and no longer waits beside the composer. Until the model reads it, the title says when it will:

go
working on it
⠰ Working
↳ subagent fix-lint completed reaches the model after tool calls
all done
 
↳ subagent audit-deps completed held · send a message to deliver

Once the report lands, the label disappears and the block moves into its turn. The composer only shows your own queued messages now.
