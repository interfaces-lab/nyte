Implemented the four P1 findings from the [initial audit](/Users/workgyver/Developer/nyte/output/core-quality-audit-2026-09-04/audit.md), corrected TUI input ownership, and installed one shared native compaction plugin in TUI and desktop. | Finding | Result |
| --- | --- |
| Tool hooks lost after waiting or recovery | The durable effect stores the final hook-adjusted content, error status, details and usage before publishing completion. Recovery reuses that result. Settlement failures still reject the batch, including when another policy decision is pending. |
| Previous summary lost on a split turn | An existing summary survives even when the next compaction has no additional history prefix. |
| Concurrent messages select the wrong agent | Agent selection travels with its keyed message through admission, cancellation and redelivery. A different agent selected during tools starts a new run at the next response boundary; same-agent steering keeps the current run. |
| Compaction receives the normal agent prompt | Assistant and compaction requests share options and hooks while retaining their own prompts and purposes. Manual compaction uses this same path. |
| Composer borders, menus and terminal focus compete | The shell owns focus. Background input is disabled while a panel owns input; border clicks leave typing in the composer. Renderer automatic focus is disabled. |
| Mouse selection misses after menu resize/scroll | Selection is scrolled into view after the renderer establishes the content and viewport dimensions. Tests click the currently rendered choice. |
| Escape ignored during pending menu work or compaction | Busy menus accept Escape. Manual compaction has an abort signal, synchronous stop dispatch, cancellation feedback and protection against a late successful result. Automatic compaction cancellation cannot start a fallback or assistant request. |
| Slow provider work can lose its lease to another runner | Leases renew during provider and tool calls. Ownership loss aborts work; publication remains fenced. Renewal stops before cleanup finishes. |
| Concurrent first session access leaks a handle | Adoption closes a losing handle after rechecking the pool following the asynchronous read. |

The [shared plugin](/Users/workgyver/Developer/nyte/packages/plugin/src/openai-compaction.ts) supports OpenAI API-key authentication and OpenAI Codex account authentication. Both hosts install it by default. It uses the standalone native `responses/compact` endpoint and preserves the complete returned output unchanged for the same provider, API and model. This follows the [OpenAI compaction guide](https://developers.openai.com/api/docs/guides/compaction) and [Codex's compact endpoint](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/endpoint/compact.rs). It does not enable the separate inline `context_management` feature.

Native success performs no local summary request. Unsupported providers, rejected or malformed native responses, and the plugin's 30-second deadline use portable compaction. Parent cancellation stops the operation. Portable history remains available for model changes; oversized recovery is summarized incrementally, with a smaller retained tail for smaller models. Branch navigation also summarizes the complete native checkpoint backup, including later facts and file changes. Context estimates use native output usage when available and label missing-usage estimates as approximate in code.
