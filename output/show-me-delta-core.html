Delta core concepts ↔ Nyte core

A conversation tree.
Files stay with git.

Delta records the conversation and the files together and reverts them together. Nyte keeps a tree of conversation commits, moves heads inside it, and leaves whole-tree file truth to the host VCS. That split is decided, not pending.

Current Nyte source and design docs compared with Delta's documentation. No runtime code changed.

01

A conversation branch is not a file branch.

Both systems persist conversations. Delta also maintains file history and materializes it on participants' machines. Nyte's kernel is git's object database with messages in place of files: no worktree, no checkout. Tools operate on the directory supplied at session activation, and git owns what is in it.

The original project stays unchanged until work is brought in. Existing Local Checkout is an alternative mode; threads sharing it are not isolated. [D1] [D2]

"One checkout per thread" has no Nyte counterpart, and that is deliberate. A client reads any commit without checking anything out; a runner reads refs at every step and materializes nothing. Two heads in one session share the directory, and isolating them (a git worktree per session, say) is a host choice, never a kernel object. [N8]

Nyte's durable conversation tree. Every path stays reachable while retention holds it; nothing is rewritten.
Head
A named ref into that tree. Client state, not a stored checkout register. Moving it is a compare-and-swap; undo is another move.
Host VCS
Where whole-tree file truth lives. The kernel records only the mutations tools declared, so a git panel knows where to look.

Delta distinguishes a Delta worktree from a Git worktree because it keeps its own file history. Nyte has neither concept in the kernel; the git worktree is the only one, and the host owns it.

02

Moving back moves the conversation. Nothing else.

heads.move re-points a head inside the session tree. The abandoned path stays reachable, and going forward again is another move. Delta documents a revert that restores the conversation and its recorded project files together. Nyte has no revert: the tree keeps every path, and files are git's to restore.

Assumes a completed run, one file included in DeltaDB, and no concurrent edits. This demonstrates the documented contract, not an execution test of Delta. Reverting files cannot undo a deployed service, an API request, or a database migration, in either system. [N3] [D3]

runs.changes folds patches from successful tool results so a git panel knows which files a run declared it touched. Whole-tree truth is the host VCS; shell writes and external edits show up there, not in the kernel. That projection is not a filesystem snapshot and was never meant to be one. [N5]
What Nyte's recovery guarantees

The durable effect record distinguishes intent from result. That is the contract, not a stepping stone to file restoration.

  • After a crash, an unsettled read or ls may run again. Unsettled bash, edit, and write calls instead report interruption. A stored result can be reused. This is not exactly-once execution. [N6]
  • A filesystem write can complete before the process records its result. Cancellation does not turn it into an undo operation. [N4]
  • The SDK refuses heads.move while a run is nonterminal. Lower-level kernel head moves can proceed; a stale runner's publish then fails and the run ends superseded. Already-performed filesystem effects remain, which is git's problem to show and yours to decide. [N3]
03

Who owns what.

Delta bundles conversation, file history, and checkouts into one thread. Nyte splits them across three owners. Every row below is current behavior; none of it is a proposal.

Decided

Kernel + SDK

packages/core/src/kernel

  • Objects, refs, leases, events. A head is a named ref into the session tree, and reading any commit is a projection.
  • heads.move and head creation are the only navigation. Undo is another move, valid while the ref event and object are retained.
  • No file revisions, no restore operation, no worktree. runs.changes records declared mutations only.
Decided

Host

Activation, VcsBackend, relocate

  • Supplies activation.env.cwd; refs/facts/cwd remembers it; relocate changes it only while the session is idle.
  • vcs.status and vcs.diff answer whole-tree questions from git. Reverting files is a git operation.
  • Decides trust for a directory before any tool runs in it.
Decided

Clients

Terminal, desktop, remote clients

  • Draw the tree, the transcript at any commit, and the changes projection next to a git panel.
  • Request head moves and show git's answer. No client implements its own file restoration.
Current binding
session→refs/facts/cwd→host VCS (git)→client git panel

Every head in a session shares that directory. A head lease protects store publication, not files. A host that wants isolation gives each session its own git worktree; the kernel never learns about it.

Why the split. A database and a filesystem do not share one transaction, so bundling them means inventing restore, conflict, and recovery protocols git already has. Git merges files because three-way text merge is well understood; there is no such operation for two conversations, which is why the kernel keeps one context parent and leaves files alone. [N8]

04

Where the models diverge, and why.

Each Delta concept below has a Nyte counterpart that was chosen deliberately. The reasons are recorded in the design doc and the kernel README, not inferred here.

  1. Thread revert → head move.

    The tree keeps every path. Moving back is one compare-and-swap on a ref; moving forward again is another. heads.move({ summary }) carries an abandoned path forward by meaning instead of replaying generated text. Nothing is reverted because nothing is destroyed.

    Decided

  2. Delta worktree per thread → none.

    A client reads any commit without a checkout. A runner reads refs at every step and materializes nothing. The head name is client state, not a stored current-checkout register.

    Decided

  3. Recorded file history → host VCS.

    Git owns whole-tree truth, including shell writes and edits made outside Nyte. The kernel keeps declared mutations from tool patches so a git panel can point at the right files, and nothing more.

    Decided

  4. Multi-machine file sync → out of scope.

    The event stream synchronizes the conversation, not files, credentials, or installed tools. relocate changes a session's directory; it never moves files. A host that needs the same files on two machines uses git for it.

    Not a kernel concern
What still has to be true
  • Two heads in one session write to the same directory. Clients should say so rather than imply isolation.
  • A filesystem write can complete before its result is recorded. Cancellation is not undo; git is.
  • Effect replay is safe or never, not exactly-once. A stored result can be reused; an unsettled write reports interruption.
  • A session directory is never a security sandbox. Absolute paths, shell commands, and external services need their own access controls.
05

Rewrite one function, or clean up after?

Walking Delta's model against Nyte end to end, the kernel needs no rewrite for any of it. The four authorities, step, heads.move, and stacks hold up. The mess is one layer up, in the SDK's session-location code, and it is a cleanup that subtracts before it adds.

kernel/*.ts
No rewrite. Nothing in Delta's thread, worktree, revert, or machine model asks for a new ref, object, lease, or event. The decisions in section 04 already answer each one.
sdk/nyte.ts location
Redesign from first principles. The session directory was bolted on: resolveSessionActivation, activationFor, requireRunnerLocation, and relocate each re-derive where the session lives. One state machine should own it.
cwd, 4 copies
refs/facts/cwd, activationState.env.cwd, activationCwd, and the tool closures built from api.env.cwd. Seven storedCwd reads exist only to check they still agree.
Pooled
An optional-field bag: activationState?, resolving?, activation?, activationCwd?, opening?, relocating?. Which combinations are legal is a comment, so it should be a discriminated union.
relocate
130 lines. The idle check runs three times (outer scan, replace, reserve), and the terminal-phase test ["done", "aborted", "failed"].includes(...) appears eight times in the file. One isIdle predicate and one lease-holding loop.
VcsBackend
The only real gap Delta's "project" exposes. vcs.status() takes no directory while sessions carry their own cwd. A host serving two sessions in two repos answers for one of them. Fix is an argument, not a kernel change.

Order of work: delete the duplicate checks and the extra cwd copies first, then introduce the union, then add the cwd argument. Each step leaves the behavior the tests already assert; none touches kernel/*.ts.
