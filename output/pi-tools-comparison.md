# Pi tools comparison

Reviewed 2026-09-12 against Pi commit [`71dca871bc80b6bc97be37f0ca3189399d651fff`](https://github.com/earendil-works/pi/commit/71dca871bc80b6bc97be37f0ca3189399d651fff), whose agent packages declare version `0.85.1`. Nyte baseline is `21a275c19e8648d3f735567cd8c2e622916df0d6` plus the current working tree. In particular, `bash.ts` and the job/kernel files already have uncommitted changes. This comparison includes them and changes no implementation files.

## Recommendation

Keep Nyte's tools and selectively port useful changes from Pi. Nyte already owns adapted copies of these tools, as documented in [the tool registry](../packages/core/src/tools/index.ts). Replacing them with a package dependency would mostly exchange local adapters for new adapters. The strongest feature to borrow is image conversion and resizing for `read`.

Pi has two relevant implementations. `pi-agent-core` exports environment-backed harness tools. `pi-coding-agent` exports local filesystem tools with extension hooks and terminal renderers. Its default coding set is `read`, `bash`, `edit`, and `write`; `grep`, `find`, `ls`, and `powershell` are available separately. Nyte enables the four coding tools plus `ls`. See [Pi's tool sets](https://github.com/earendil-works/pi/blob/71dca871bc80b6bc97be37f0ca3189399d651fff/packages/coding-agent/src/core/tools/index.ts).

## Per-tool findings

| Tool | Concrete differences | Decision |
| --- | --- | --- |
| `read` | Text paging and the 2,000-line/50 KiB head limit already match. Nyte detects images by content and returns their original bytes, omitting BMP. Pi's harness offers an injectable image processor; its CLI implementation converts unsupported inline formats and resizes by default. Nyte also attaches a relative-path title. | Keep the tool; borrow the processor option and conversion/resizing behavior if improving image support. |
| `bash` | Both stream combined output, retain a 2,000-line/50 KiB tail, save truncated full output, and support timeout/cancellation. Nyte owns its process backend, throttles output updates to 100 ms, adds titles, and exposes `background` for its durable job system. Pi's harness delegates process/capture work to `ExecutionEnv.exec` and marks changed output checkpoints at two-second intervals. | Keep. Replacing it is an execution/runtime integration project, with little improvement in ordinary command behavior. |
| `edit` | Both support multiple disjoint replacements against the original file, fuzzy fallback, duplicate/overlap rejection, BOM/line-ending preservation, mutation serialization, and diff/patch details. Nyte precomputes fuzzy content/needles and assembles replacements in one forward pass. Pi additionally normalizes a single object in `edits`, including a JSON-encoded object, into an array. Nyte accepts arrays, JSON-encoded arrays, and legacy top-level `oldText`/`newText`. | Keep the existing algorithm and performance changes. Consider Pi's extra input normalization only if actual model output warrants it. |
| `write` | Both create parent directories and serialize mutations. Nyte first reads existing contents and returns a diff, unified patch, first changed line, and title. Pi's harness returns no write details and does not read the old file first. That also means Nyte can reject an overwrite when it cannot read the old file, while Pi delegates only the write. | Keep. A direct replacement removes reviewable write diffs. |
| `ls` | Both include dotfiles, sort case-insensitively, append `/` to directories, default to 500 entries, and apply the byte cap. Both expose replaceable filesystem operations. Nyte adds boundary parsing, titles, and abort checks after awaited operations. Pi adds extension context and terminal rendering. | Keep. No useful listing behavior gain from replacing it. |
| `grep` and `find` | Nyte intentionally uses search commands through `bash`. Pi offers dedicated tools using `rg` and `fd`, with match/result limits, ignore handling, context, and structured truncation notices. Their default backends invoke Pi's binary availability/download helper. | Keep excluded. Nyte intentionally uses `bash` for search, including file finding. |
| `powershell` | Available in Pi's full registry, absent from Nyte's registry, and absent from Pi's default four-tool coding set. | Defer unless native PowerShell is a product requirement. |

## Why a package swap is not small

The harness factories are public exports of `@earendil-works/pi-agent-core`; there is no separately published tools package in the inspected manifests. Its tools receive Pi's environment, invocation, and execution context rather than Nyte's signal/update/context arguments. The dependency brings Pi AI, telemetry, and Chord alongside Nyte's own implementations. Using the CLI factories avoids the harness calling convention but brings the coding-agent package, its terminal dependencies, and image worker/WASM packaging. No bundle-size measurements were made. See [agent exports](https://github.com/earendil-works/pi/blob/71dca871bc80b6bc97be37f0ca3189399d651fff/packages/agent/src/index.ts), [agent dependencies](https://github.com/earendil-works/pi/blob/71dca871bc80b6bc97be37f0ca3189399d651fff/packages/agent/package.json), and [CLI dependencies](https://github.com/earendil-works/pi/blob/71dca871bc80b6bc97be37f0ca3189399d651fff/packages/coding-agent/package.json).

Any adoption still needs Nyte's argument parsing, result titles, prompt contributions, durable replay policy, and write diffs. Preserve [the tool binding](../packages/core/src/tools/bind-tool.ts) and [filesystem plugin](../packages/core/src/plugins/builtin/tools-fs.ts), which marks only `read` and `ls` safe to replay after a crash.

Mutation locking also differs. Nyte shares one process-wide queue keyed by real path. Pi's harness scopes queues to the `ExecutionEnv` object and canonical path. Creating one environment per session would no longer serialize simultaneous edits from different sessions to the same local file. An adapter would need a shared environment or Nyte's existing queue. See [Nyte queue](../packages/core/src/tools/support/file-mutation-queue.ts) and [Pi queue](https://github.com/earendil-works/pi/blob/71dca871bc80b6bc97be37f0ca3189399d651fff/packages/agent/src/harness/tools/file-mutation-queue.ts).

## Suggested follow-up

1. Add an optional image processor to Nyte's read tool and provide conversion/resizing at the host boundary. Keep plain core execution free of mandatory image-library setup. Verify large images, BMP conversion, conversion failures, cancellation, and the packaged desktop/TUI builds.
2. Keep a pinned upstream revision in port provenance when next touching tool source. Compare behavior and tests before importing later fixes. The current comments link moving `main` URLs.
3. Revisit direct harness reuse only when Nyte needs a shared execution environment for local and remote files/processes. Evaluate the environment abstraction and tools together, while preserving Nyte's durable job and replay semantics.

This was a source review, including whitespace-insensitive algorithm diffs and existing tool tests. No runtime parity benchmark was run, and no Pi dependency or tool migration was applied.

## Implemented follow-up

Nyte now processes image reads directly in the existing `readImage` helper, using `@cf-wasm/photon/node` and `exifr`. Small supported images retain their original bytes. BMP conversion, dimension and base64 payload limits, and EXIF orientation are handled before attaching processed images. The self-contained WASM dependency avoids a new host callback, worker, or asset-copying layer. `find` and `grep` remain intentionally excluded.
