Shortcuts by context

The focused composer, completion list, panel or selection determines what a key does. Test that context, not just the key. Editor defaults below reflect Nyte’s installed OpenTUI 0.5.10; confirm them again when upgrading.

Ctrl = ControlMeta = decoded modifier, often Alt/OptionSuper = Command/Windows when reported

Modified Enter, Super shortcuts and some Alt combinations depend on what the terminal sends. Run the same cases with negotiated Kitty keys and ordinary terminal escape sequences. Printable characters, including ?, remain text. Keypad Enter is explicitly bound in the composer and completion; verify it separately in panels whose handlers accept Return. Feature coverage

Each group needs a successful path, cancellation where offered, and a visible failure path. Plugin and provider features appear only when their contributions are present.

No waiting before feedback

Every keypress is a latency case, in idle chat, streaming chat and cancellation. Local editing and navigation must not wait for network, database, provider or tool work.

Meaning of zero latency: zero awaited external work before the local state changes, followed by the next render opportunity. Measure the elapsed time rather than claiming a physically impossible zero-millisecond display.

Action Immediate feedback Asynchronous work
Each character, delete, cursor or selection key The edit or cursor change appears without waiting. Undo and redo are included. No fetch, persistence or transcript rebuild on the editing path.
Enter → transcript Capture the draft and show a pending user message in the transcript immediately. The composer accepts the next draft. Prepare attachments and await ordered configuration/admission. Distinguish pending from durable; preserve failures for retry.
Streaming + typing Every edit remains responsive while tokens, reasoning, tools and child updates arrive. Batch background presentation work. Do not let event bursts monopolize keyboard processing.
Parent cancel Show “Stopping…” on the next frame and suppress duplicate stop actions. Cancel the parent and its subagents, including backgrounded children. Show “Stopped” only after the outcome is confirmed.
Selected subagent cancel The selected task shows “Stopping…” without freezing navigation or typing. Verify the child and its owned work stop. Do not cancel its parent or siblings.
Question arrives The question takes input ownership before its first interactive frame. Its keys cannot also invoke composer actions. Wait for the explicit answer. Escape dismissal must not grant consent or send a chat message.

Measure every action, not an average session

  • Record each input’s PTY-write timestamp and the first matching emulated screen/cursor state.
  • Report p50, p95 and maximum by action, terminal, viewport, and idle/streaming/cancelling state.
  • Hold every data source deliberately. Edits, panel shells, skeletons and selection changes must still appear before the held source is released.
  • Record startup and steady-state cases separately. Never hide a stalled key behind a good aggregate average.

Keep slow work away from input

  • Host execution and synchronous database work need an execution context separate from terminal input and rendering.
  • Bound client-side background event processing. A native output thread alone does not isolate application JavaScript.
  • Use cached local choices for navigation. Loading indicators describe actual pending reads, not artificial delays.
  • Keep immediate feedback, durable admission and actual process termination as separate measured outcomes.

Requested acceptance criteria. The binary-PTY suite and latency budgets have not yet been implemented or measured. Terminal window scanout remains a separate real-terminal measurement.

What does “stop” stop?

A disappearing spinner is not proof of cancellation. Observe the parent, child, task state and tool process separately.

These are expected-behavior cases, not a record of passed PTY tests. Run each with a child held at a known point so it cannot finish before the cancel key arrives.

Stop a parent with an active foreground child

  1. Launch an isolated Nyte binary and request a child that runs a controlled long tool.
  2. Wait until the child is visibly running. Record the parent and child identities.
  3. Focus the composer with no selection or popup, then press Esc.
  4. Inspect Tasks, the child conversation and the controlled tool’s completion/termination signal.
  5. Resume the session in a fresh binary process and inspect the durable result.

Verify: the cancellation policy in the matrix, no orphan process, and a composer that accepts the next message.

Background first, then stop the parent

  1. Start foreground child work and use Ctrl+Z to move it to the background.
  2. Confirm the background transition before pressing Esc in the composer.
  3. Inspect the background child and confirm that parent cancellation stopped it too. In a separate run, use Ctrl+X to verify selected-child cancellation without stopping the parent.

Verify: parent stop cancels every subagent it owns, including backgrounded children. Selected-task stop affects only that task. Closing the browser cancels neither.

Cancel around completion and a pending question

  1. Repeat parent stop while a child is starting, running a tool, asking a question, and completing.
  2. Repeat with child-owned foreground/background commands and two independently running tasks. Built-in child agents cannot delegate grandchildren; verify that attempted delegation is rejected.
  3. Check that a late completion or late provider chunk cannot turn a stopped task back into a running one.

Verify: one terminal outcome per task, no unintended answer or consent, and sibling tasks follow the intended scope.

Cancel UI work without cancelling captured messages

  1. Hold model discovery, paste a draft and press Enter before paste completes.
  2. Complete the paste and wait for draft capture. Type another draft, then clear it with Ctrl+C.
  3. Fail model discovery. Inspect the captured message, the new draft and provider activity.
  4. Repeat while switching sessions and while retrying a rich inline-skill message.

Verify: clearing later input cannot release an earlier message’s configuration gate. The failed message returns without duplicated skill instructions or lost attachments.

01 / Identity

Know which binary ran

  • Build the CLI before QA. Keep the previous binary if compilation fails.
  • Record absolute binary path, hash, version, source revision and OpenTUI version.
  • Drive that binary. Do not import Interactive or construct a replacement Nyte app inside the runner.
02 / Isolation

Own every side effect

  • Fresh HOME, workspace, settings, credentials and database for each independent case.
  • Local scripted providers and tools for deterministic running, failure, retry and cancellation states.
  • Separate opt-in checks for real login, provider access, clipboard and updates. No production credentials or sessions.
03 / Terminal I/O

Connect both directions

  • PTY output goes to terminal.write().
  • Forward both encoded input and terminal query replies from onData back to the PTY.
  • Propagate onTerminalResize to the child. Focus the embedded terminal before sending keys.
  • Do not reserve the same Escape or Ctrl+C keys in the driver that Nyte must receive.
04 / Evidence

Assert observable results

  • Read terminal.screen() after paint, including cursor position.
  • Wait for a matching screen or controlled service event with a deadline, rather than arbitrary sleeps.
  • Record PTY output, inputs with timestamps, final screens and process exit status.
  • For cancellation, inspect tool lifetime and reopened task state. For submission, inspect the controlled provider’s received payload.
05 / Stress

Repeat under load

  • Empty workspace; empty chat in a busy workspace; short and large histories.
  • Widths 32, 80, 120 and 160 columns; short windows; repeated resize.
  • Rapid typing, key bursts, slow output consumption, streaming, catalog refresh and multiple children.
  • Direct terminal and tmux. Report latency distributions separately, not a single “instant” claim.
06 / Real terminal pass

Check what the emulator cannot show

  • Ghostty VT renders the character grid, not child Kitty graphics or Sixel images. Inspect image previews in a real supporting terminal.
  • Check OS clipboard, IME composition, browser authentication and external-editor handoff interactively.
  • Measure key-to-emulated-screen separately from terminal window presentation. PTY timing does not measure display scanout.
  • Close the child and PTY, restore terminal modes, and account for every spawned process.

Clean exit, one copyable command

Restore terminal modes, finish cleanup and print any diagnostics first. When a session exists, every graceful shutdown ends with these two lines: 

To resume previous session
nyte --session=<session-id>

The second line contains only the command with the actual session ID, quoted safely when needed. No prefix, prompt symbol or extra message on that line. Ctrl+C, /quit, SIGINT and SIGTERM keep the same teardown guarantees; their exit statuses remain appropriate to the cause. Without a saved session, omit the resume hint.
