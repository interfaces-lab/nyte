Nyte is a small core for cross-platform agentic UI.

You should be able to read the code that runs your agents. Nyte keeps the agent loop, the durable kernel, session storage, five coding tools, and the provider blocks in one workspace, written here rather than imported.

Nothing calls back up the stack. A client talks to createNyte. That object admits into a store. A runner advances the run one step at a time, and the turn reaches a provider through a function it was handed.

Design

The whole shape of Nyte in the order the code runs: what is stored, who may write, and how a turn reaches a provider.

The model in git terms

Nyte stores a thread the way git stores a repository. Messages are immutable objects. A head is a named ref that points at one of them. Moving a head is the only way a thread changes, and every move is an event the store can replay. Nothing about a turn lives outside those three things.

The seam only flows one way. A client talks to createNyte; that object admits into a store; an attached runner advances the run one step at a time; the turn reaches a provider through a function it was handed. Four tables own the state, and each has one writer.

sdk.tsCopy
import { createNyte } from "@nyte-ai/core";

const nyte = createNyte({ store, runner, stream });

const head = await nyte.send({
  thread: "password-reset-404s",
  content: "Find out why reset links 404 after yesterday's deploy.",
});

The four authorities

Four tables own the state. Each has exactly one writer, so a bug can be placed by asking which table it corrupted.

  • Objects — content-addressed messages, never rewritten.
  • Refs — heads by name, moved only by admission.
  • Leases — one runner per run, renewed every step.
  • Events — the log the other three are replayed from.

Heads are named refs

A thread has one head per branch. Editing a user message does not rewrite history; it creates a sibling object and moves the head. The old branch stays reachable by name until it is pruned.

The turn

Respond, then tools. The runner asks the provider for one step, admits whatever comes back as objects, and only then executes the tools that step requested. A turn aborted mid-step leaves objects behind, never half a ref.
