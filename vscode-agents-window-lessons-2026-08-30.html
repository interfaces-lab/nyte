Desktop and terminal research / second pass

Nyte shipped the room and lost the signal

Six days on, the project has a typed wire protocol, pinning, archiving, split panes, drag placement, a labelled workbench, and a terminal-side task browser. Almost every structural recommendation from August landed somewhere. The one thing the report was actually about did not: a session row still reduces every state an agent can be in to one blinking blue dot, and that blue is the same blue as the focus ring.

Research scope: VS Code 1.120 through 1.135 Nyte scope: core, protocol, TUI, and desktop at c0be400 New material: a colour-script rule taken from film
01 / verdict

The structure landed. The signal did not.

The August report asked for room, truth, and relationships. Nyte built the room. It built the relationships in the terminal. It has not yet built the truth, and it has now spent its whole colour budget on decoration, so there is nothing left to say a state with.

Recommendation

Stop adding surfaces. Do four things: filter the root pickers with parent: null, render the five states the sidebar already computes, give the desktop the delegation card the TUI already has, and adopt a colour script so that at any moment exactly one saturated hue is doing work on screen.

9 / 13

Most of the plan landed

Nine of the thirteen August items shipped, three of them by a better route than the one recommended. The scorecard below lists all thirteen.

12 / 27

Children still leak

Forty-four per cent of the inspected store is child sessions. The word parent does not appear anywhere in the desktop sidebar, search palette, or host.

1 dot

Five states, one dot

The filter menu classifies every session as needs-attention, unread, working, draft, or done. The row draws a dot when working and nothing otherwise.

02 / what moved

Six days changed the architecture, not the row

The rename to Nyte came with a real structural change: a @nyte-ai/protocol package now owns one frozen verb table, and core, the client, the TUI, and the desktop bridge all read the same types from it.[14] That is the contract cleanup the August report asked for, done more thoroughly than it asked. SessionInfo gained pinned, archived, and a parent record naming the agent, the run, the call, and the depth.

The reversal worth defending

Refusing the 272px sidebar was a reasonable call. Nyte answered density with a hover preview card instead, and a preview card is a better home for a repository path than a permanent second line. The problem is what the card carries: repository and folder, after a 600ms delay. It says where the task lives, never what the task is doing.

The reversal that is not defensible yet

The filter menu offers pull-request state, cloud versus local environment, and fourteen session sources including Slack, Linear, and two named bots. None of those facts exists. The filter hard-codes every session to no pull request, local, and desktop, so those three dimensions can only ever remove rows or leave them alone. unread is worse: it has a label, a sort position, and a filter checkbox, and no code path can ever produce it.

03 / what VS Code built

A session is a task envelope

VS Code defines a session as the conversation, workspace, changes, and execution state for one task. The Agents window is a manager for those sessions across workspaces and machines.[1]

That definition drives the layout. The left region answers "Which task needs me?" The center answers "What happened and what should I say next?" The right region answers "What did the task produce?" Chat is central, but it is not the whole object.

The design changed in public

The current window is the result of several revisions, not a finished pattern dropped into place. The sequence matters because it shows what VS Code kept and what it later removed.

1.120
The Agents window reached Stable as a preview for managing tasks across projects.[2]
1.123
Multiple root sessions could open side by side through a menu, drag, or Alt-click.[3]
1.128
Workspace-free quick chats, multiple chats in a session, and read-only subagent chats arrived.[4]
1.131
Running subagents began showing model, elapsed time, and current tool in the parent conversation.[5]
1.135
VS Code made the single side pane the default, simplified the session header, and moved session facts above the composer.[6]

The lesson is not "add three panes"

The lesson is ownership. Session navigation, conversation, and evidence have separate jobs. Nyte kept its right panel closed by default and still made its job obvious, which is the version of this lesson that actually shipped.

04 / useful details

The small decisions carry the product

Regular sessions get 54px, quick chats get 28px

VS Code's current source fixes regular session rows at 54px. Quick chats and nested chat rows use 28px.[7] This is not arbitrary padding. The regular row has a title line and a details line for workspace or harness, diff totals, status, and time. A quick chat has no workspace or review burden, so it earns the compact row.

The details line changes with state

When a task is working or needs input, VS Code hides stale workspace, diff, and time details and gives the line to current status. When the task settles, the normal metadata returns.[8]

The icon is not one overloaded dot

The domain has Untitled, In progress, Needs input, Completed, and Error. Running and needs-input states use different animated forms. Failure is red. Unread state is a separate input to the icon renderer.[9]

Grouping has explicit precedence

Archived wins over pinned, which wins over a custom group, quick chat, then workspace or date. Pin and ordering are local presentation state. Archive comes from the session provider.[10]

A session list is an attention queue. If every row looks idle, the interface has stopped managing agents and become a transcript picker.

Session facts moved to the next-decision point

In 1.135, VS Code moved changes, pull requests, issues, browser activity, and artifacts to pills above the composer. Those facts matter when the user decides whether to steer, review, or finish the task. The shared header became quieter at the same time.

Nyte took a different route to the same end. Instead of a pill above the composer, the 40px icon rail became a 210px labelled workbench rail carrying Changes +241 -18, Browser, Terminal, and Files. The placement lesson was honoured; the placement itself was not copied. Artifacts still wait for a typed core contract, correctly.

A subagent looks like delegated work, not a file read

VS Code first exposes a running subagent in the parent transcript. The pill names the task and model. Beside it, elapsed time updates. Under it, the current tool changes in place. Selecting the pill opens the child's full read-only conversation while the parent remains available.[5]

Nyte's TUI now does exactly this, and does it well. A task index lists children with sessions.list({ parent }), opens a live follower per child, and classifies each into eight states: queued, running, waiting, retrying, stopping, stopped, done, and failed.[20] The inspector renders the child's own transcript read-only. The desktop has none of this. Its tool vocabulary covers read, bash, edit, write, and ls; task is not in the table, so a delegation renders as an anonymous row inside a folded work group.[18] The wire seam is still open too: TaskDetails.childSessionId is typed string where the design says SessionId.[16]

Side-by-side work needs words

VS Code supports Open to the Side, drag and drop, and Alt-click for root sessions. A later UX study tested clearer split controls with five participants. The sample is too small for a broad claim, but every participant struggled with icon-only controls. The recommendation was a labeled Split view action with a one-window divider icon, plus drag for people who discover it.[11]

For Nyte: settled

This one is finished. The context menu has a labelled Open to the side, drag and drop landed with five edge placements, the layout is capped at two panes, and the focused pane is tracked explicitly. Pinning was not reused to mean layout.

VS Code also learned to delete controls

The 1.135 header revision cites qualitative research and telemetry showing that most customers create one chat per session. VS Code removed the prominent New Chat control and shows chat tabs only when a second chat exists.[12]

This is the sharpest lesson in the whole study. A mature agent interface does not get better by shrinking every row. It gets better by removing the wrong hierarchy. Nyte did not add chat tabs, which was right. It did add a filter menu with three dimensions and one status that no data can populate, which is the same mistake pointed the other way: adding hierarchy the domain has not earned.

05 / the colour script

Film spends one colour at a time, and so should a session list

Before a frame is animated, a feature film is painted as a colour script: a strip of small thumbnails, one per sequence, that fixes the dominant hue of each beat. The point of the exercise is not to choose pretty colours. It is to decide the order in which colours are allowed to arrive, so that no two of them compete for the same moment.[24]

The rule underneath it is simple. A sequence gets one prominent colour. Everything else in the frame is desaturated toward neutral. When the next colour finally appears, the audience reads it as an event, because it is the only thing that changed. A film that shows every colour at once has a palette; a film that shows one colour at a time has a language.

A colour only means something if the frame before it was quiet. Spend every hue at once and you have not built a palette, you have built noise with a legend.

An interface is one continuous shot

A session manager never cuts. The user sits in the same frame for hours while agents start, stall, ask, and fail inside it. That makes the colour-script discipline more important here than in film, not less: there is no scene change to reset the eye, so every saturated pixel that is always present permanently raises the floor that a real signal has to clear.

Nyte currently spends its colour budget on things that never change. The status dot that means "an agent is running" is painted with fillAccent, which is also the focus ring, the selection fill, the link colour, and the primary button.[21] The one hue reserved for "this needs you" is the same hue as "your cursor is here".

The terminal palette has thirteen leads and no lead

The TUI theme declares thirteen saturated roles that can appear in a single scrollback screen. Two of them are the same value: running, the colour of a working agent, is #08c0ef, and so is operator, the colour of every arrow and equals sign in every code sample the assistant prints.[22] A transcript containing one fenced TypeScript block already puts cyan, pink, green, magenta, orange, and blue on screen before any agent has done anything.

Source observation Values read from the dark theme roles. The desktop compounds it: code blocks are highlighted with GitHub's own themes, so a second colour system with no relationship to the Nyte tokens renders inside the same conversation.[23]

The rule to adopt

C

At any moment, exactly one saturated hue is doing work on screen. It belongs to the most urgent live state, and it is the only element allowed to be both saturated and animated. Everything else falls to neutral until its own beat arrives.

That gives a directory a real order of precedence, which is the colour script written out as a table. Read it top down: the first row whose condition is true owns the frame.

Needs input amber, still

A parked call is waiting on a person. This is the only state where the product is blocked on the user, so it outranks everything and it does not animate.

Still colour reads as a held frame. Motion here would read as progress.

Failed red, still

A settled run ended in failure and no one has looked. Red appears nowhere else in the chrome, so it never has to shout.

Clears on open. A failure the user has read is history, not a signal.

Working cyan, breathing

An agent is live. This is the state Nyte draws today, and the only one it draws. It keeps the pulse, and it stops sharing a token with the focus ring.

Motion is the signal. The hue only distinguishes it from a settled row.

Recovering neutral, breathing

An orphaned run whose host will resume it. It is alive, so it moves. It needs nothing from the user, so it gets no hue at all.

Motion without colour is the cheapest honest way to say "wait".

Everything else neutral, still

Idle, done, drafted, archived, pinned. Weight, position, and grouping carry these distinctions. None of them earns a hue.

Unread stays out of the colour system entirely. It belongs to title weight, which is a separate channel and can safely coexist with any state above.

What this buys

  • A saturated pixel in the sidebar always means one specific thing.
  • Failure never has to compete with syntax highlighting for attention.
  • The accent stays free for interaction: focus, selection, links.
  • Reduced-motion users lose the pulse but keep the hue, and the reverse.

What it costs

  • Syntax highlighting must desaturate inside the transcript.
  • Thinking text gives up purple. Indentation and weight carry it instead.
  • The user tint slider must not be able to reach the state hues.
  • running and operator can no longer be the same value.

Where the tint slider fits

The appearance panel already lets a user rotate a hue and set an intensity across chrome, editor, and sidebar surfaces. That is compatible with a colour script, and actually strengthens it, as long as the four state hues are excluded from the rotation. A user who tints the shell magenta must still see the same amber for "needs input" that everyone else sees.

06 / Nyte now

The terminal now leads the desktop

The most interesting thing to happen since August is a reversal. The TUI, which had no hierarchy story at all, now models delegated work better than the desktop does. It discovers children by parent, follows each one live, classifies eight run states, and opens any of them as a read-only inspector. The desktop, which got panes and a workbench, still renders a subagent as an unnamed row in a folded group.

The correctness bug survived its own fix

In August the blocker was structural: the bridge and the strict IPC validator had no parent field, so the correct query could not be sent. That blocker is gone. parent is in the shared verb table, typed as a nullable session id, and the TUI already uses it. The desktop simply never asks. The word parent appears nowhere in the sidebar, the sidebar view model, the search palette, or the desktop host.[15]

The store inspected at c0be400 holds 27 sessions, 12 of which carry a parent fact. Forty-four per cent of the desktop's root picker, its search palette, and its drag-and-drop source list is delegated work that the user never created and cannot usefully reopen from there.

The same omission reaches the terminal by a different route. nyte resuming the latest session sorts every session by last activity with no parent filter, so resuming right after a delegation finishes can drop the user inside the subagent's session rather than their own.[20] The interactive resume picker does better: it keeps children in the list but labels them <agent> subagent, which is a defensible alternative to hiding them, and a better answer than either product had in August.

The poll got heavier while the pagination got fixed

Pagination is genuinely fixed. loadSessionDirectory follows Page.next to the end, so search and grouping now see every session rather than the first two hundred. The cost is that it does this inside a query that reruns every five seconds, and there are now two such queries: the workspace directory and the session preview list.[19] Each tick reads the entire local store, page by page, and throws it away.

The reason is unchanged and honestly documented in the file's own header comment: there is no cross-session watch verb. The verb table has watch for one session and nothing that spans them. This is now the single highest-value addition to the protocol, because every directory improvement in this report needs it and none of them can afford another poll.

A second defect rides along. The search query key is the search text alone, with staleTime: Infinity and no workspace identity, so repeating a search after switching folders can serve the previous folder's results.[19] This was already recorded as an outstanding finding in the cleanup audit and remains open.

The state is computed, sorted, filtered, and then not drawn

This is the sharpest finding of the second pass. The sidebar view model has a statusOf function that reads each session's heads and returns needs-attention, working, draft, or done. That value drives a status grouping, a status ordering, and a status filter menu.[17] The row component then ignores it entirely and recomputes a single boolean, drawing a dot when any head is running and nothing at all when it is not.

So a user can group the sidebar by status, see a heading that reads Needs attention, and find under it a row visually identical to every done row above it. The information is present, correct, and already flowing. It stops one component short of the eye.

needs-attention is derived from a run phase of waiting, which is a durable kernel fact rather than an inferred idle state. That resolves the August open question: the directory can honestly say "input needed" without the SDK growing an ask vocabulary, because parked calls are already in the run phase. Recovering and settled-failure still need the core projection the August report described.

Delegation is solved in one product and untouched in the other

The TUI's task index is the design this report asked for. It lists children by parent with full cursor paging, keeps a live follower per child, tears followers down when a child disappears, and reduces run phase plus abort intent into eight named states.[20] The status line reads 3 tasks · 2 active · 1 done and the inspector opens the child's own transcript.

The desktop's tool presentation table covers read, bash, edit, write, and ls. Anything else falls through to a humanised tool name, so task renders as the word "task" inside a folded work group summarised as "Worked for 42s".[18] A minute of delegated agent time and a directory listing get the same row. This is unchanged from August, and it is now the largest gap between the two clients.

The diagnosis

Nyte's problem is no longer compression. It is that the desktop has been growing outward, into panes and terminals and browsers, while the row at the centre of the product has not changed since the first report. The facts it needs all exist now. Someone has to spend a day rendering them.

07 / a Nyte-shaped answer

Keep one session model and expose its relationships

VS Code has sessions containing chats. Nyte has durable sessions, branches, and child sessions. Those models rhyme, but they are not interchangeable. The four laws below survived the rewrite unchanged; the fifth is new, and comes from the colour script.

1

A root session remains the task a user names, searches, opens, archives, and places beside another root task.

2

A child session remains a durable delegation. It appears inside its parent's transcript and opens in an inspector. It does not appear in the root picker.

3

A split pane is another view of a session id. It is not a new chat type and does not change the durable tree.

4

Durable run truth belongs in core. Collapsed groups and pane arrangement remain desktop policy. Pinning and archive moved into core since August, and that was the right call: they are facts about the session, not about one window.

5

A filter dimension may ship only once a session can actually differ along it. A control that can only ever remove nothing is a promise the product has not kept.

What not to copy

No chat collection inside a session

Nyte already has branches, forks, and child sessions. A second chat entity would duplicate ownership and complicate recovery. This warning was heeded.

No permanent customizations panel

VS Code has a broad editor and extension product to expose. Nyte's session manager should not become plugin settings navigation.

No filter fiction

This warning was about workspaces in August and it went unheeded elsewhere. Pull request state, cloud environment, and fourteen session sources are all in the filter menu, and all hard-coded to one value. Delete them until the data exists.

No icon puzzle

Keep icons for repeated compact controls. Use text for split view, task state, and review entry points until their meaning is learned.

08 / build order

Four days of rendering, not another surface

The August sequence was four slices of building. This one is much shorter, because the data now exists. Three of the four items below are wiring facts that are already computed into pixels that are already reserved.

Slice A
Half a day

Filter the root pickers

  • Pass parent: null from loadSessionDirectory. The verb, the schema, and the bridge already accept it.
  • Pass it from the search palette query too.
  • Give targetSession the same filter, so resuming the latest session cannot land inside a subagent.
  • Keep the TUI resume picker's labelled children. Hiding is right for the root list; labelling is right for an explicit chooser.
Slice B
One day

Draw the state the sidebar already knows

  • Have the row read statusOf instead of recomputing a boolean, so the grouping headings and the rows agree.
  • Give the status mark its own token. It must not resolve to fillAccent.
  • Apply the colour script: amber, red, cyan, neutral, in that precedence.
  • Grow the row to a second line only when a state is live. Reserve the status slot at all times so nothing reflows.
  • Put the same state into the hover preview card, beside the repository and path it already shows.
  • Delete unread, pull requests, environments, and sources from the filter menu, or make one of them real.
Slice C
One to two days

Bring the desktop level with the terminal

  • Align TaskDetails.childSessionId with SessionId and validate transcript details at the desktop edge.
  • Take task out of generic tool grouping.
  • Render agent, child state, and an Open child action, matching the TUI's eight states.
  • Open the child in the second pane. The split layout already exists, so a child inspector needs no new surface.
Slice D
Protocol

Retire the polls

  • Add a cross-session watch verb to the shared verb table. This is the only new protocol surface the report asks for.
  • Drop both five-second directory queries once it lands.
  • Add a latest-settled-outcome summary to the directory projection, so failed and stopped can persist without an N+1 query.
  • Put workspace identity in the search query key and give it a finite stale time.
  • Add a lease-derived recovering signal, so an orphaned run stops reading as idle.

Stop conditions across the sequence

✓No child session appears in the root list, the search palette, or the latest-session resume.
✓A row under a Needs attention heading looks different from a row under Done.
✓At most one saturated hue is visible in the sidebar at any moment, and it is never the accent.
✓Every filter dimension can partition a real store into two non-empty sets.
✓A running delegation opens its child transcript in one action, in both clients.
✓Directory state follows a watch, not a five-second poll, and neither poll remains.
✓Repeating a search after switching workspaces never returns the old folder's rows.
✓Routine read, list, and shell calls still fold into quiet work groups.

Do not start here

A third pane, an artifact framework, cloud sessions, pull-request integration, and cross-workspace aggregation can all wait. The filter menu already advertises three of those, which is how this list got long enough to need saying twice. None of them fixes the row.
