---
title: files.format
description: Returns the given contents formatted for the file at that path, without writing it.
---

Formats contents as the file at that path would be formatted, without writing anything. A local
workspace runs the first formatter that handles the file's type: `oxfmt`, `prettier` or `biome`
for JavaScript, TypeScript, JSON, CSS, HTML, Markdown and YAML (`oxfmt` also takes TOML), and
`ruff` for Python. It looks in the project's `node_modules/.bin` and `.venv` first, then on the
`PATH`, and passes the path so the formatter finds its config. A `.go` file runs `gofmt` from the
`PATH` alone, so it runs no project code. It answers `formatted` with the new contents,
`unchanged`, `unavailable` with the reason when no installed formatter handles the file's type, or
`failed` with the reason when one ran and errored, such as a non-zero exit or a binary that can't
start.

## When to call it

From a "format document" action or format on save, before writing the result with
[`files.write`](/docs/reference/operations/files/write).

## Access

Any principal with `participant` authority. Workspace scope, with the `files` capability.

## Example

Request body:

```json
{
  "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0",
  "path": "src/date.ts",
  "contents": "export const today=()=>new Date()\n"
}
```

Response:

```json
{ "kind": "formatted", "contents": "export const today = () => new Date();\n" }
```

## Errors

- `unavailable` or `denied` when the workspace doesn't offer files. A missing formatter is the
  `unavailable` outcome and a failing one the `failed` outcome, not errors.
