---
title: language.status
description: Lists the workspace's language servers and their state.
---

Lists one row per language server the workspace has started: its language, program, project root, state, version and executable. A server is `starting`, `ready`, `busy` with a progress title, `missing` with the command that installs it, `untrusted` while the folder isn't trusted, since a server runs code from it, and stopped again when trust is withdrawn, `failed` with a reason, or `idle` after it shut down for want of use. There is one server per language and project root, the nearest folder holding a `go.mod` or `go.work` for Go (`gopls`), a `pyproject.toml`, `ruff.toml` or `.ruff.toml` for Python (`ruff`), and a `tsconfig.json`, `jsconfig.json` or `package.json` for TypeScript and JavaScript (`typescript-language-server`). A TypeScript or JavaScript file also gets an `oxlint` row when an oxlint configuration sits in its folder or above it; that server only reports diagnostics. A server installed in the project's `node_modules/.bin` or `.venv` runs before one on `PATH`.

## When to call it

To show which servers run and why one answers nothing. To follow changes, use [`language.watchStatus`](/docs/reference/operations/language/watch-status).

## Access

Any principal with `participant` authority. Workspace scope, with the `language` capability. Paths are relative to the workspace, or absolute; answers name files inside the workspace by their relative path and others, such as the standard library, by their absolute one. Lines are zero-based and columns count UTF-16 code units.

## Example

Request body:

```json
{ "workspace": "9b1f0c7e5a2d48e3b6c4f1a0d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0" }
```

Response:

```json
[
  {
    "language": "go",
    "server": "gopls",
    "root": "",
    "state": { "kind": "ready" },
    "version": "v0.24.0",
    "executable": "/Users/ada/go/bin/gopls"
  }
]
```

## Errors

- `unavailable` or `denied` when the workspace doesn't offer language intelligence.
