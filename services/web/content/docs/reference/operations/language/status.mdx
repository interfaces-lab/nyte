---
title: language.status
description: Lists the workspace's language servers and their state.
---

Lists one row per language server the workspace has started: the languages it serves, its name, project root, state, version, executable and the features it answers. A server is `installing` while its pinned version downloads, `starting`, `ready`, `busy` with a progress title, `missing` with the command that installs it, `untrusted` while the folder isn't trusted, since a server runs code from it, and stopped again when trust is withdrawn, `failed` with a reason, or `idle` after it shut down for want of use. `features` is empty until the server is ready, and grows when a server registers a feature after it started.

Every server that takes a file gets it, each with its own row per project root, the nearest folder holding one of its marker files: a `go.mod` or `go.work` for `gopls`, a `pyproject.toml`, `ruff.toml` or `.ruff.toml` for `ruff`, and a `tsconfig.json`, `jsconfig.json` or `package.json` for `typescript-language-server`. Some servers take a file only when their configuration sits in its folder or above it, as `oxlint` does. A server installed in the project's `node_modules/.bin` or `.venv` runs before one on `PATH`. One found in neither is downloaded at a pinned version into `~/.nyte/language-servers`, once the folder is trusted. A server that has no download, or whose download failed, is `missing`.

## When to call it

To show which servers run and why one answers nothing. To follow changes, use [`language.watchStatus`](/docs/reference/operations/language/watch-status).

## Access

Any principal with `participant` authority. Workspace scope, with the `language` capability. Paths are relative to the workspace, or absolute; answers name files inside the workspace by their relative path and others, such as the standard library, by their absolute one. Lines are zero-based and columns count UTF-16 code units.

## Errors

- `unavailable` or `denied` when the workspace doesn't offer language intelligence.
