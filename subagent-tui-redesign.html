Subagent delegation surfaces: what exists, and a light redesign

Everything below is drawn from the shipped code paths in packages/tui/src. The proposal keeps the same renderables, menu API, and theme roles — it only changes what those rows say and which role colors them.

What the inventory shows

  • Eight distinct states all render in the same foreground gray; the palette already has running, ok, error, warning unused here.
  • mode · state · title spends the leftmost, most-scanned characters on the two lowest-entropy fields.
  • Duration is buried mid-description even though MenuItem.status gives a right-aligned column for exactly that.
  • The agent name — the thing that says who is working — is the last field anyone reads.
  • Model and thinking level are the two settings that most change what a delegated run costs and how good it is, they are per-agent configurable, and they are invisible on every subagent surface. You can override an agent's model and get no confirmation that the override took.

3. Proposal — Tasks menu

Same single-line rows, same MenuItem shape. Status becomes a colored glyph, the agent leads, the title carries the row, model and thinking level get their own column, and elapsed time moves to the right.

4. Make the glyph vocabulary global

The map above should not belong to the task browser. One exported helper — say statusGlyph(status): { glyph, role } next to GLYPHS — and every surface that reports the state of work draws from it. Today each of these picked its own convention independently, and they nearly agree, which is the worst case: close enough to look intentional, different enough to misread.

Rule that keeps this from rotting: components never name a glyph or a color for a status, the same way theme.ts already forbids naming a hex. They pass a status and get both back.

7. Proposal — fixed-height delegation window

The current card is height-unstable by construction. render() picks between clearBody() and showPreview() on every sync, driven by whether the live progress text happens to fit inlineToolPreview's single-line test, and then renderSettled() chooses again from the result. A delegation that was three rows tall becomes one row the moment it finishes, and everything below it jumps.

how the height moves today, one delegation, no user input t+0.4s 1 row heading only, progress text empty t+6s 1 row progress fits inline → clearBody() t+9s 4 rows progress gained a newline → showPreview() t+22s 7 rows longer output, 3 head + 3 tail t+31s 2 rows next progress string is short again settled 1 row summary fits inline → clearBody() every transition reflows the transcript below it

The fix: reserve the space once

A delegation opens a window of exactly three rows the moment the call starts, and that window is three rows until the card is destroyed. Rows are the child's last three transcript items — one item per row, never wrapped, truncated at the terminal edge. The window tails: a fourth item pushes the first out. Nothing below the card ever moves, because nothing about the card's box ever changes.

Rules that make the height guarantee real

  • Reserved, not grown. Three rows exist from the first frame, blank-padded at the bottom. Fewer than three items never means a shorter card.
  • Items, not lines. One child transcript item per row — tool call, thinking, assistant text — so information per row stays constant. Raw progress text is what makes today's card breathe.
  • Never wrap. wrapMode: "none" with truncation. A wrapping row breaks the guarantee on every resize.
  • Settling changes color, not geometry. The glyph goes ✓, the last row becomes the answer, the height does not move. This is the whole point: the transition that jumps today is the one you watch most.
  • The tail ends on the result. Because the final assistant message is the newest item, the frozen window's last row is the answer — the summary comes for free instead of needing a separate collapsed state.
  • Overflow is counted, not hidden. Row one becomes · 13 earlier steps once items scroll out, so the card never lies about being complete.

Cost, and the one escape hatch

Four rows per delegation, permanently, in scrollback. That is the price of never jumping, and it is the right default: a delegated turn is the part of a session you most often re-read. ctrl+o — already the tool-output toggle, already wired through ToolOutputExpansion — collapses a settled window to its heading. Collapsing is then a deliberate act with a keystroke behind it, not something the renderer does to you mid-stream.

Open

  • Three rows is the fixed size. It holds the newest step, its predecessor, and the overflow count — enough to see the rhythm, cheap enough that three concurrent delegations cost 12 rows rather than a screen.
  • Concurrent delegations each own a window. At three rows this stays affordable, so no shrink-when-crowded rule is needed — which is good, because that rule would be a height change, exactly what this section forbids.
  • A child that spawns its own child still gets one row. Nesting the window recursively is a different feature.

8. What this does not change

  • No new keybindings, no change to Task, JobInfo, or the jobs API.
  • projectTasks, taskStatus, taskLabel, taskActivity stay as they are; only the formatting layer in choices(), repaint(), and TaskInspector.show() moves.
  • Model and level are read from each child's existing state.config. No new fetch, no new event, no plumbing into core.
  • Legacy-console fallbacks continue to hold, since every glyph comes from GLYPHS.

The delegation window is the one piece that is not a formatting change: the task branch in ToolCard.render() stops sharing the clearBody/showPreview path with every other tool and gets a fixed row set of its own, fed by the child items TaskIndex already follows.

Decisions worth making before this is built

  • Routing waiting children into the background status line changes what that row competes for.
  • Going global with the glyph means touching tool cards and activity labels in transcript.ts — the highest-traffic surface in the app — for consistency's sake alone. Worth it only if the vocabulary is settled first; doing it twice is worse than not doing it.
  • Four permanent rows per delegation. If that is too much for long sessions, the alternative is auto-collapse on settle — which brings the jump back. Pick one; there is no version without a cost.
