# Workbench file rendering review

All repository paths below are relative to `/tmp/review-code`. Cursor paths refer only to the installed implementation supplied in the task. Observations are from source and read-only API probes, not a running-app replay.

## 1. How it works today

Explorer clicks and transcript file references call `fileActions.open`, which stores a path-only file tab and navigation coordinates, without resolving an editor type (`packages/app/src/workbench/files-panel.tsx:280`, `packages/app/src/workbench/open-reference.ts:37`, `packages/app/src/workbench/file-store.ts:196`, `packages/app/src/workbench/controller.ts:44`). `FilesPanel` mounts `WorkspaceFileEditor` for every file tab; it calls `useWorkspaceFile`, whose query key contains only the path and whose query obtains files from the globally selected workspace (`packages/app/src/workbench/files-panel.tsx:485`, `packages/app/src/workbench/file-editor.tsx:201`, `packages/app/src/queries.ts:168`, `packages/app/src/queries.ts:592`, `packages/app/src/query-keys.ts:37`). The SDK sends `files.read` with a workspace ID; the host binding forwards to the core workspace capability, which exposes the provider's files API (`packages/sdk/src/workspace.ts:70`, `packages/sdk/src/workspace.ts:123`, `packages/host/src/serve/binding.ts:438`, `packages/core/src/env/workspaces.ts:233`, `packages/core/src/env/workspaces.ts:349`, `packages/core/src/env/environment.ts:179`). On desktop, SDK fetch runs over a MessagePort handed through Electron main to the host utility process, not a main-process image reader (`packages/desktop/src/renderer/src/install-bridge.ts:44`, `packages/desktop/src/main/index.ts:545`, `packages/desktop/src/main/host-process.ts:81`, `packages/desktop/src/main/host-entry.ts:176`, `packages/desktop/src/main/host.ts:384`). The local provider accepts absolute paths unchanged, returns `missing` for absent files, `large` above 1 MiB, and otherwise strict UTF-8 text without NUL or `binary`; the protocol validates that result (`packages/host/src/local/provider.ts:73`, `packages/host/src/local/files.ts:79`, `packages/host/src/local/files.ts:102`, `packages/host/src/local/text.ts:1`, `packages/protocol/src/codec.ts:112`). The app mounts Pierre only for `text`, displays static binary/large messages, and mistakenly treats `missing` as loading (`packages/app/src/workbench/file-editor.tsx:204`). Changes follows a separate patch-to-CodeView route, not this file-open route (`packages/app/src/workbench/changes-panel.tsx:840`, `packages/app/src/workbench/stacked-diff.ts:24`).

Therefore the missing-result fallthrough is real, and out-of-workspace reads are not categorically blocked. The reported path is absent in this review environment. I did not inspect the original app's query cache or connected host, so I cannot claim why that host lacked the file at the time. ## 3. Proposed target shape

### Learn the resolver approach, not the implementation

The installed media-preview manifest registers a built-in image custom editor for `jpg,jpe,jpeg,png,bmp,gif,ico,webp,avif,svg`, and separate audio/video editors. It does not register a PDF editor (`/Applications/Cursor.app/Contents/Resources/app/extensions/media-preview/package.json:1`). Its built code registers the image provider, opens a resource URI, restricts local resource roots, uses webview resource URLs, watches changes, and offers standard text/binary fallback when preview loading fails (`.../extensions/media-preview/dist/extension.js:1`, `:25`, `:38–49`).

In the installed workbench bundle, `findMatchingEditors`/`getEditor` choose registered editors using resource patterns, priority and user associations; the wildcard text editor is a separate registration (`/Applications/Cursor.app/Contents/Resources/app/out/vs/workbench/workbench.desktop.main.js:18433`, `:17541`). Text-file resolution catches a binary result and resolves a binary model. The binary editor supplies metadata and an action that invokes the editor picker (`.../workbench.desktop.main.js:19659`, `:17539`). Names such as `BinaryFileEditor` are minified; the retained ID is `workbench.editors.files.binaryFileEditor` at line 11547. The MIME table includes images and PDF at line 87, but a MIME entry alone is not a PDF renderer.

Nyte needs the same separation of resource identity, content inspection and renderer selection. It does not need an extension marketplace or general-purpose registration service for three built-in renderers.

### One resolved resource, one renderer decision

1. **Normalize the open request.** Explorer, transcript, canvas links and Changes produce the same `ResourceRef` plus optional line/column/range and renderer override. Use a discriminated source: workspace file, host-external file, or immutable Git/snapshot side. Include host identity; include workspace identity where it owns the resource. A revision reference must retain the actual revision and old/new path, not merely a scope label.
2. **Authorize and inspect at the owning host boundary.** Resolve the source to a regular file or stored revision, inspect metadata and a bounded byte prefix, and return a validated resource descriptor. It identifies text with encoding, image with a supported MIME, PDF, unknown binary, missing, or directory. Keep size/renderer limits separate from kind. Reinspect when the resource version changes, not independently in each component.
3. **Use one small app resolver.** Exhaustively map the descriptor to text, image, PDF or a terminal placeholder. Query pending/error is outside that switch. SVG defaults to image preview but retains an explicit Open source choice. A renderer override selects another valid view; it does not falsify the file kind.
4. **Load content only for the selected renderer.** Editable text keeps the existing buffer and content-hash save checks. Image/PDF renderers consume typed bytes, not UTF-8 strings or base64 hidden inside a text document. A resource-level store owns refresh, cancellation and content disposal. Release readers and revoke blob URLs on resource replacement/close.

Use signatures/magic bytes for supported raster formats and PDF, with normalized extensions as hints. SVG needs explicit XML/SVG identification, not merely “valid UTF-8”. Mismatched or corrupt content must reach a preview error or a safe fallback, never silently become trusted HTML. Decode errors are terminal renderer states with Retry/Open source or external actions, not another indefinite loading state.

Keep the existing tool-oriented `FilesApi.read` contract rather than adding UI renderer branches to every text-tool consumer. Its existing callers include read/edit/write tools, mentions and prompt loading (`packages/core/src/builtins/environment.ts:128`, `:153`, `:179`; `packages/core/src/engine/mentions.ts:28`; `packages/core/src/extend/resources.ts:675`). Add a read-only resource-resolution contract for workbench viewing, backed by the same file inspection/byte-reading operation. This is a distinct task, not a second filesystem implementation. Share classification with `FilesApi.read` and populate byte MIME there too; do not keep two MIME guesses. The current attachment fallback map at `packages/core/src/builtins/environment.ts:27–36`, `:685–693` can then be removed when providers return classified MIME.

### Safe reads outside the workspace

The present local `FilesApi` intentionally accepts absolute paths and is not a workspace sandbox. It also serves ancestor context files and tools. Do not “fix” preview access by fencing every existing file operation to the workspace or by assuming an absolute path belongs to the desktop.

For resource viewing, use an explicit host-external reference and a read-only capability for the requested file. The owning host validates the path, resolves symlinks, checks access and issues a resource handle; byte requests use that handle rather than an arbitrary renderer-supplied path. Bind access to the authenticated principal and selected resource. If policy requires approval outside workspace roots, request it for the resolved file. Do not automatically grant its parent directory. External viewing must not grant save, format or directory traversal rights. Explicit desktop-local opens and remote-host paths must remain distinguishable in the UI.

Reuse the SDK/host byte transport and host filesystem implementation. Do not introduce `host.readFile` in preload as a competing path or expose arbitrary paths through the desktop asset protocol. The existing scheme only serves selected app/canvas assets (`packages/desktop/src/main/renderer.ts:75–95`; `packages/desktop/src/account/policy.ts:88–124`).

For bounded images, use a MIME-typed Blob URL and `<img>`. Display SVG only as an image, never by injecting its markup. The app CSP already permits blob images; it does not permit `<object>` or blob frames (`packages/desktop/src/account/policy.ts:53–59`). For PDFs, use a bundled PDF renderer/worker against the byte source, not an unreviewed `<object>` or an assumption that Chromium's native PDF viewer works inside this panel. Retain the current `object-src 'none'` policy. Until a PDF renderer is shipped, show an explicit PDF placeholder with Open externally/Download, not “binary cannot be edited”. Opening locally with the OS needs a narrow desktop action; `host.openExternal` currently opens safe web URLs and `revealPath` only reveals a file (`packages/desktop/src/main/index.ts:360–362`). Remote files require a deliberate download/local-open action.

## 4. First changes

1. Fix the exhaustive document-state switch now. Add File not found and Retry, and move resource recovery above the text renderer. This removes the demonstrated false spinner without pretending to solve media rendering.
2. Carry host/source/workspace identity from open action through tab, query, read, watch and save. Normalize transcript locations at this boundary. This prevents the new media path from inheriting ambiguous ownership.
3. Implement shared bounded classification and the read-only resource byte route. Add the image renderer for PNG/JPEG/GIF/WebP/SVG, with explicit limits, decode errors and SVG source view. Do not use the text-size cap as the media cap.
4. Add source-aware Open file/before/after actions in Changes and use the same opener for transcript/canvas links. Supply immutable side bytes where the provider supports them; otherwise show an honest unavailable result.
5. Add the PDF renderer and meaningful large-text/unknown-binary fallbacks, then derive toolbar actions from renderer capabilities. Remove the superseded MIME/path/state branches as callers migrate.
