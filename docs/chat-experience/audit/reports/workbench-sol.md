# Workbench logic review

Source paths are relative to `/tmp/review-code/`. This is a source review, not a replay of the running app. "Observed" describes code; "Consequence" describes the behavior that follows from it.

## 1. How it works today

`SessionScreen` derives the workbench view from the selected workspace path and mounts it beside the chat panes, while `Titlebar` independently reads the same global snapshot to render its tabs and controls (`packages/app/src/screens/session-screen.tsx:165-188`, `packages/app/src/chrome/titlebar.tsx:126-149`, `:239-248`). `controller.ts` owns per-path tab order, active ID, expansion, layout and width, validates/restores local storage, deduplicates opening requests, and delays some tab insertions until the panel chunk loads (`packages/app/src/workbench/controller.ts:199-206`, `:548-650`, `:661-690`, `:728-828`). `workbench.tsx` also owns a three-workspace mount cache, launcher commands, rail selection, panel routing, sidebar state and resizing (`packages/app/src/workbench/workbench.tsx:54-76`, `:133-152`, `:196-288`, `:328-479`, `:510-521`). Files share one panel; their navigation, previews and draft mirrors live in `file-store.ts`, but the actual document buffer and autosave timer live in the editor component (`packages/app/src/workbench/workbench.tsx:609-619`, `packages/app/src/workbench/file-store.ts:87-109`, `:196-235`, `packages/app/src/workbench/file-editor.tsx:240-253`, `:326-377`). Changes resolves the focused chat, comparison source, patch scheduling, review marks and destructive commands inside its component (`packages/app/src/workbench/changes-panel.tsx:438-564`, `:609-678`, `:714-741`, `:897-943`). Terminal processes and streams already live outside React in `terminal-store.ts`; browser events have an external mirror, but opening and retaining the native page still depend on `BrowserPanel` mounting (`packages/app/src/workbench/terminal-store.ts:91-107`, `:352-409`, `packages/app/src/workbench/browser-surfaces.ts:50-102`, `packages/app/src/workbench/browser-panel.tsx:427-479`). The rail's cost/context rows follow the focused session, and its branch/change rows follow workspace Git status (`packages/app/src/workbench/workbench.tsx:196-205`, `packages/app/src/workbench/rail-status.tsx:115-124`, `:189-192`).

### The reported rail, reconstructed

- **Open Tabs** enumerates available entries in `view.tabs`, not a deduplicated tool list (`packages/app/src/workbench/workbench.tsx:208-210`, `:251-268`). Multiple terminals are legal instances; agent terminals are separately identified by session/job, while user terminals are deliberately never deduplicated (`packages/app/src/workbench/controller.ts:667-674`). Do not "fix" this by filtering all tabs by kind.
- **On nyte** enumerates available tool kinds without subtracting open kinds (`packages/app/src/workbench/workbench.tsx:273-288`). Its missing Changes launcher is explained by the separate Git-status Changes row (`:205`, `:234-240`, `:280`).
- **Terminal, Terminal** can therefore result from two rail launches. Both initially have the literal title `Terminal` (`packages/app/src/workbench/terminal-store.ts:358-365`). A later shell title may distinguish them, but the rail has no fallback instance discriminator.
- **The external PNG** can enter through the file-reference opener, then retain its full path because it is outside the view-key prefix (`packages/app/src/workbench/open-reference.ts:43-48`, `packages/app/src/workbench/file-store.ts:122-130`). The normal Files route only renders a text editor; a normal PNG produces the binary/large/error state, not an image preview (`packages/app/src/workbench/file-editor.tsx:201-220`). This traces a supported absolute-path input into an unsuitable, unclassified tab. It does not prove which click created the user's particular tab.

## 3. Proposed target shape

Use one small, pure workbench model for tab identity and navigation rules. Do not put terminal streaming, native browser placement, Git execution and document editing into a larger replacement controller.

```text
workbench/
  model.ts                 state, events, pure reducer, tab/resource identity
  selectors.ts             rail rows, launchers, tab items, panel visibility
  store.ts                 publication and subscriptions
  persistence.ts           storage schema, decode, encode, coalesced writes
  commands.ts              user intents; calls workspace-bound feature operations
  react.ts                 useSyncExternalStore selectors
  workbench.tsx            stage composition only
  panel-host.tsx           render selected slots and deferred renderers
  rail.tsx                 render selected rows and dispatch their intents
  rail-status.tsx          status-row presentation
  tab-strip.tsx            tabs, sorting gestures, focus and confirmation views
  layout.ts                pure width/bounds calculations
  side-panel.tsx           resizable inner panel, not navigation policy
  browser/
    surfaces.ts            native surface identity, holders, event mirror
    placement.ts           bounds/occlusion/focus attachment to a DOM slot
    panel.tsx              address bar, controls and page slot
    ...                    existing address/find/history/bookmark modules
  changes/
    model.ts               resolved comparison identity and navigation/review selectors
    session.ts             focused-session subscription and scope resolution
    commands.ts            bound Git actions, revert, mark-viewed operations
    panel.tsx              toolbar/sidebar/stack composition
    ...                    existing patch loader, viewed/options stores and views
  files/
    tabs.ts                file navigation, preview/pin/close transactions
    documents.ts           one document object per open file target; autosave lifetime
    document.ts            existing pure document state machine
    panel.tsx              toolbar, explorer and editor composition
    editor.tsx             Pierre adapter and DOM selection
    ...                    existing file tree, empty state and search
  terminal/
    store.ts               existing shell/job process state and persistence
    runtime.ts             existing Ghostty rendering adapter
    panel.tsx              status, controls and canvas attachment
  canvas/
    panel.tsx
    activity.ts
  open-reference.ts        translate a reference into one command
```

The model should distinguish resource identity from presentation state:

- Files/Changes tool roots are singleton tabs per view. File documents use a normalized resource target, not a label or raw path spelling.
- User terminals are distinct instances. Agent terminals use session/job identity. Launching an existing terminal and creating another shell are different events.
- Browser tabs refer to native surfaces. URL/title are mutable page facts, not identity.
- Changes UI scope resolves to a workspace/session/run comparison before constructing cache and review keys.
- Opening, preview replacement, pinning, scope selection and activation are atomic transitions. Chunk readiness cannot make an otherwise-open tab invisible to the model.
- Pure selectors accept typed snapshots. Host/SDK calls and storage stay at boundaries. DOM focus, pointer capture, address drafts and widget selection remain view concerns.

The renderer cache can still limit mounted widgets to three workspaces. It must not decide whether an open document or native browser page exists. Likewise, extracting direct effects into a differently named hook would not solve ownership; remove the mirrored state and use mount subscriptions or callback refs for the remaining imperative attachments.

## 4. First changes

1. Fix the browser handoff contract to retain the actual agent surface. Stop adopting the first Browser tab by URL.
2. Make workspace/file/comparison targets explicit and bind Git APIs before asynchronous workflows. Classify external files before opening a project editor.
3. Extract the pure tab model and commit opens immediately. Move preview replacement and pinning into that transaction; remove the hidden pending-tab model.
4. Centralize launcher/New/reveal commands and derive the rail once. Make the changed-files status row select uncommitted scope, even when Changes is already open.
5. Give each resolved Changes comparison a workspace/session/run key and use it consistently for patches, viewed marks and navigation state.

### Verification and limits

Read the controller, panel implementations, feature stores and mounting code; searched production callers before identifying duplicated commands and mirror ownership. Traced the browser issue through the app bridge into the desktop's native surface registry, and checked the local Files implementation before judging external paths. Read existing controller, file-store, browser-surface and cold-open tests to distinguish their asserted behavior from untested consequences. No tests, Electron sessions or dev servers were run. The two cold-file sequences, cross-chat review leakage, workspace-switch workflow and fourth-workspace browser eviction are source-derived consequences, not recorded runtime reproductions. No source files were changed; this report is the only file written.
