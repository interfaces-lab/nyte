# UI token leveling review

All paths below are relative to `/tmp/review-code`. Observations come from source, not rendered comparisons. Proposed values retain Nyte's existing steps unless a migration is called out.

## How it works today

The system has three useful layers, but consumers can bypass their relationships. `packages/ui/src/styles/theme.stylex.ts:3-5,566-588` builds numbered color ramps; `packages/ui/src/styles/roles.stylex.ts:32-99` maps them to content, background, border, material and shadow roles. `packages/ui/src/styles/tokens.stylex.ts:22-70,72-327` declares typography, a 4px spacing unit, motion and component measurements, including coarse-pointer variants. `packages/ui/src/styles/vars.stylex.ts:4-102` exposes color/type/motion/shadow handles, while `packages/ui/src/styles/schema.stylex.ts:5-24,58-179` exposes spacing, geometry and stacking handles. `packages/ui/src/styles/text.stylex.ts:5-21` pairs some font sizes with leading. The app adds structural measurements and its own heading recipes in `packages/app/src/theme/tokens.stylex.ts:6-86` and `packages/app/src/theme/settings-patterns.stylex.ts:6-38`. Appearance independently changes UI and code font sizes at `packages/app/src/theme/boot.ts:53-54`. Restyle contracts constrain property categories, not token levels, at `packages/ui/src/styles/contracts.ts:54-67,127-135,334-355`; the design lint constrains selected literals at `packages/app/lint/design-scale.js:596-605`. The token lock checks declared property and handle names, not their values or relationships, at `packages/ui/scripts/check-tokens.mjs:33-57`.

## Proposed target shape

### Leveled token map

Numbers below are nominal defaults. UI text scales with the UI-size input; code text scales with the code-size input. Leading rounds upward as it does today. A role alias may share a value with another role, but it must reference the same level rather than repeat the literal.

| Scale | Steps and role mapping |
|---|---|
| **UI type** | `caption` 11/14 for timestamps and compact metadata; `small` 12/16 for small labels; `body` 13/18 for controls, rows and descriptions; `bodyCompact` 13/16 only for explicitly compact content; `section` 15/24 for section/dialog headings; `title` 19/24 for the existing canvas heading tier; `pageTitle` 24/32 for settings pages; `display` 28/34 for usage figures and About. Pair tracking and weight with recipes. Keep regular/medium/semibold at 400/500/600. Rename the ambiguous `font2xl` tier to `title` during migration, not delete it: it has five consumers across canvas and lab. |
| **Code type** | `codeSmall` 11/16 for tool excerpts and metadata; `codeCompact` 12/16 for shell previews; `code` 12/18 for ordinary code blocks; `codeReview` 12/20 for diffs. Derive all four from the code-size input, including their leading. The ordinary and review defaults already exist at `packages/ui/src/styles/tokens.stylex.ts:41,50` and `packages/app/src/theme/tokens.stylex.ts:85`. Keep prose heading ratios as a separately named relative type recipe, not miscellaneous literals in `create()`. |
| **Spacing** | Retain 0, physical 1px, then 2/4/6/8/10/12/16/20/24/32. Map 2 to fine separation, 4 to label grouping, 6 to dense row/menu gaps, 8 to sibling controls and prompt block/image spacing, 10 to prompt inline spacing, 12 to group padding, 16 to block/prose spacing, 20 to settings row inline padding, 24 to dialog padding, 32 to larger sections. Add the already-used 40/48/80 large rhythm steps for settings section spacing and page padding. Move ordinary turn gap 14 to 16. Keep native offsets, masks and text-relative indentation outside this rhythm scale. |
| **Control size** | Retain visual button tiers 16/20/24/28/32/36 and their existing coarse tiers 28/32/36/40/44/48. Input tiers alias 28/32/36; row tiers alias 28/32; avatars alias 20/24/28/36. Keep hit targets separately at 24/44. Make target clamping explicit in recipes: an input's current coarse `md` height is effectively 44 because of `minHeight: target.min`, despite its 40px size token at `packages/ui/src/input.tsx:110-137`. Do not call visual size and hit-target size the same measurement. |
| **Glyphs and slots** | Ink levels `xs/sm/md/ml/lg/xl` = 12/14/16/18/20/24. Compact disclosure arrows use 12, standard row icons 14, toolbar/file icons 16, large icon-only controls 18, provider/launcher icons 20, empty-state icons 24. Slots use independently named 14/16/20 levels. Migrate the generic 15px `box` slot to 16; preserve a spinner-specific optical frame only if comparison proves it needs one. |
| **Radius** | Core shape levels 0/2/4/8/12/16/pill. The existing raw 2px chart/indicator corners become a real level. Control-size recipes may derive intermediate 6 and 10 from those levels; coarse control radii remain explicit size mappings. Derive menu outer 14 from item 8 + inset 6, command outer 20 from item 12 + inset 8, and segmented outer radius from the selected control radius + its 2px inset. Keep composer 22 and native-frame 6 as private geometry roles, not additional general shape levels. |
| **Content and color** | Retain primary/secondary/tertiary/disabled for importance, separate from hue and interaction state. Preserve the current normal base pairs: content 130/30, 100/70, 70/100, 40/120 and interactive content 120/20, 100/50, 80/90, where each pair is light/dark. Tint changes the ramp, not the ordering. Descriptions use secondary, incidental metadata and stopped copy tertiary. Chrome may remain a contextual role with its distinct dark mapping; it is not another universal text level. Keep background base/muted/elevated/chrome as purposes, not a falsely linear brightness ladder across both modes. Rename border secondary/primary/strong to subtle/default/strong to make strength readable. |
| **Elevation** | `e0` none; `e1` current small for controls/sticky content; `e2` current medium geometry for tooltips, trays and workbench overlay; `e3` current large for menus/popovers; `e4` current extra-large for dialogs/command. Preserve current geometry initially. Apply an independent contour recipe when needed. Remove `shadowWorkbench` after moving its one app consumer to the chosen level, and move the medium geometry out of `roles.stylex.ts`. Stacking order remains the separate existing `layer` scale. |
| **Motion** | Transition levels `none/instant/fast/normal/slow/extended` = 0/50/100/150/200/300ms. State feedback uses fast, ordinary expansion normal, larger state entry slow, morph/text roll extended. Shared easing roles cover state feedback, popup entry and switch movement using the existing curves. Reduced-motion variants belong to these transition tokens. Repeating indicator periods and interaction delays retain separately named component roles rather than being forced onto a transition scale. |

## First five changes

1. Fix the code/UI typography dependency split and add complete heading recipes. Check the supported UI/code preference extremes, not just 13/12.
2. Bound icon ink sizes and separate slots. Migrate the repeated disclosure, row and toolbar roles first.
3. Restore interactive color ordering under tinted scopes and replace the two stopped-copy mixes with tertiary.
4. Merge prompt read/edit geometry, alias repeated header/spacing values, and delete the two unused suggestion properties.
5. Unify transition durations and the CSS/Motion boundary. Add the corresponding lint and value-level token checks alongside each migration so the same bypass cannot return.

## Verification and limits

Read-only source searches covered app StyleX usage and token references across `packages` and `scripts`. The icon count used the installed Babel parser and JSX nodes rather than a text-size grep. Two `pnpm exec oxlint --threads=1 --config oxlint.config.ts --format json` runs checked ten representative files: About, file-type icon, workbench styles, tool line, UI input, turn styles, composer styles, prose styles, usage styles and app theme tokens. Both exited 0 with no diagnostics.

No dev server was started. No snapshot files were changed. Full tests, typecheck, rendered comparisons and contrast measurements were not run. The normal token checker was inspected rather than executed because its reader writes temporary modules at `packages/ui/scripts/tokens.mjs:82-87`; this review was limited to writing this report.
